## 7. 陀螺仪零漂与累计误差是否能解决

| 问题 | 当前代码已有措施 | 能解决到什么程度 | 仍然缺什么 |
| --- | --- | --- | --- |
| 上电零漂 | `imu_app.c:72` 启动即调用 `JY61P_StartGyroCalibration()`；`jy61p.h:45` 设定 `200` 个样本；`jy61p.h:42` 采样周期 `10 ms` | 若上电时车体静止，约 `2 s` 后可得到较好的陀螺零偏均值 | 需要规范“上电静止”流程，并能让上位机看到 `imu_calibrated` 状态 |
| 航向归零 | `ZERO` 命令调用 `JY61P_ZeroYawReference()` | 可以把当前朝向重置为 `0` | 这只是参考系重置，不等于漂移被根治 |
| 累计误差 | `jy61p.c:183` 使用角度项 `0.02` 做航向融合 | 只能“抑制一部分漂移”，不能从工程上宣称“已经解决累计误差” | 缺少运行期重标定、温漂补偿、里程/外参融合、航向闭环 |
| 长距离直线 | 当前没有“以 yaw 误差修正 `wz`”的控制器 | 不能保证长距离直线 | 需要增加航向 PID、速度闭环、里程标定 |

### 结论

| 问题 | 结论 |
| --- | --- |
| 陀螺仪零漂能否解决 | 可以“通过静止标定显著减弱”，但不能简单认定为彻底解决。 |
| 陀螺仪累计误差能否解决 | 目前不能。当前代码只有基础融合与零点重置，没有完整的长期抑漂方案。 |
| 小车能否长距离直线行驶 | 现阶段不建议直接给出“可以”。最多只能做低速、短距离联调验证。 |

## 8. 激光近距离急停能力与急停距离判断

### 8.1 代码层急停条件

| 条目 | 代码依据 | 数值 |

| 上层急停联锁 | `remote_cmd.c:168-195` | 激光无效或 `laser_warning >= 3` 立即锁车 |

### 8.2 可以实现什么

| 问题 | 结论 |
| --- | --- |
| 小车能否在激光识别近距离物体时急停 | 可以，前提是当前运动链路走的是 `RemoteCmd` 这条主流程，且激光在线。 |
| 急停是软件急停还是物理继电器断电 | 当前是软件/协议层急停，通过 `Mecanum_EmergencyStop()` 下发给电机。 |

### 8.3 “急停距离是多少”的准确回答

| 口径         | 结论                                                                |
| ---------- | ----------------------------------------------------------------- |
| 代码触发距离     | `150 mm` 过滤距离以内，且连续 `2` 次确认后触发                                    |
| 实际物理停止距离   | 不能仅靠源码给出，需要实车标定                                                   |
| 为什么不能直接下结论 | 真实停止距离还受到 `50 ms` 测量周期、`2` 次确认延迟、主循环调度、Modbus 下发延迟、电机驱动器响应、车体惯性影响 |

### 8.4 按当前参数的理论接近量估算

| 车速 | 仅由“两次确认延迟”带来的额外接近量 |
| --- | --- |
| `0.05 m/s` | 约 `5 mm` |
| `0.20 m/s` | 约 `20 mm` |
| `0.60 m/s` | 约 `60 mm` |

上表还没有把串口发送延迟和机械惯性算进去，所以它只能作为“下限级估算”，不能代替实测。  
建议把“安全急停门限”先从 `150 mm` 提高到一个更保守的实测值，再做高速测试。

## 10. 下一步工程架构方向：树莓派 + 两块 STM32

### 10.1 建议的职责分层

| 节点 | 主要职责 | 不建议承担的职责 |
| --- | --- | --- |
| 树莓派 | 视觉识别、目标理解、任务调度、路径规划、日志记录、上位机通信 | 直接做电机实时闭环、直接输出底层 PWM |
| 底盘 STM32 | IMU/激光采集、急停联锁、底盘速度闭环、路径动作原语执行 | 视觉推理、大量字符串处理 |
| 机械臂 STM32 | 关节控制、夹爪控制、限位/原点管理、动作执行反馈 | 视觉识别、全局任务规划 |

### 10.2 通信架构建议

| 阶段 | 建议方案 | 原因 |
| --- | --- | --- |
| 短期联调 | 树莓派 <-> 底盘 STM32：沿用 `USART2` 文本协议；树莓派 <-> 机械臂 STM32：独立 UART/USB-UART | 改动最小，最快出结果 |
| 中期稳定版 | 统一成“帧头 + 长度 + `msg_id` + `payload` + `CRC`”的二进制协议 | 文本协议便于联调，但不适合长期双板协同 |
| 长期扩展 | 形成“树莓派主控 + 两块 STM32 从控”的统一消息总线 | 便于新增传感器、机械臂状态和任务反馈 |

### 10.3 结合当前板级资源的建议

| 资源 | 现状 | 建议用途 |
| --- | --- | --- |
| `USART3 / PB10 PB11` | 已用于底盘电机 Modbus | 保持专用，不要再挂传感器调试流 |
| `USART2 / PA2 PA3` | 已用于 `RemoteCmd` | 作为树莓派到底盘 STM32 的主控制链路 |
| `USART1 / PA9 PA10` | 已初始化，但业务层未使用 | 优先给“调试回传”或“第二块 STM32 通道”使用 |

### 10.4 推荐的消息层划分

| 方向 | 建议消息 |
| --- | --- |
| 树莓派 -> 底盘 STM32 | `HB`、`SET_VEL`、`STOP`、`ESTOP`、`ZERO_YAW`、`RUN_SEGMENT`、`CLEAR_FAULT` |
| 底盘 STM32 -> 树莓派 | `STATUS`、`IMU`、`LASER`、`ODOM`、`FAULT`、`ESTOP_REASON` |
| 树莓派 -> 机械臂 STM32 | `HOME`、`SET_JOINTS`、`SET_POSE`、`GRIP_OPEN/CLOSE`、`PICK`、`PLACE` |
| 机械臂 STM32 -> 树莓派 | `ARM_STATUS`、`AT_TARGET`、`LIMIT`、`FAULT` |

### 10.5 项目目录方向建议

| 目录 | 内容 |

| `chassis_stm32/` | 当前底盘工程，继续负责底盘、IMU、激光、安全联锁 |
