# 工程整合过程说明

## 整合目标

将 JY61P 姿态模块、ATK-MS53L1M 激光测距模块和 ZDT-X42 麦克纳姆轮运动模块整合到同一套 STM32CubeIDE 工程结构中，形成稳定的传感器读取、桥接转换、底盘运动控制流程。

## 整合流程

| 阶段 | 内容 | 结果 |
|---|---|---|
| 资料检查 | 检查两个 zip 的文件结构 | 两个包均为 `Core/Inc`、`Core/Src` 模块包，未包含完整 CubeIDE 元数据 |
| 传感器导入 | 导入 JY61P、ATK-MS53L1M、`imu_app`、`laser_app`、`sensors`、`board_app` | 形成 `Board_App_Init()` 与 `Board_App_Loop()` 统一入口 |
| 运动模块导入 | 导入 `mecanum`、`chassis_control`、`motor_manager`、`modbus_rtu`、`zdt_x42_modbus` | 形成 `Mecanum_Init()`、`Mecanum_SetVelocity()`、`Mecanum_PeriodicTask()` 底盘入口 |
| 桥接层新增 | 新增 `sensor_bridge.h/c` | 将 deg/mm 转换为 rad/m，并提供 `SensorSnapshot_t` |
| 主循环整合 | 新增 `Templates/main_integrated_example.c` | 实现传感器更新、快照读取、安全急停、底盘周期任务，避免复制后与 CubeMX 默认 `main.c` 重复编译 |
| 后续空间 | 新建 `UserModules` 目录 | 预留导航、通信、任务规划等模块接入空间 |

## 主循环数据流

| 顺序 | 函数 | 作用 |
|---|---|---|
| 1 | `Board_App_Loop()` | 轮询 IMU 与激光传感器，更新统一传感器快照 |
| 2 | `Sensor_GetSnapshot(&snap)` | 将传感器快照转换为运动控制更适合的 rad/m 单位 |
| 3 | 安全判断 | 激光失效或距离过近时调用 `ChassisControl_SetExternalEmergency(1)` |
| 4 | `Mecanum_*()` | 正常时下发底盘目标速度 |
| 5 | `Mecanum_PeriodicTask()` | 周期计算四轮转速，通过 Modbus 下发电机 |

## 桥接层字段说明

| 字段 | 单位 | 来源 |
|---|---|---|
| `yaw_rad` | rad | `car_yaw_est_deg` |
| `gyro_z_rads` | rad/s | `gyro_yaw_dps` |
| `pitch_deg`、`roll_deg` | deg | IMU 姿态应用层 |
| `distance_m` | m | `laser_filtered_distance_mm` |
| `laser_warning` | 0-3 | warning、slow、too_close 三级合成 |
| `fault_flags` | bit mask | IMU 无效、激光无效、距离过近 |

## 后续模块接入建议

| 模块 | 建议接入点 |
|---|---|
| 上位机/蓝牙/串口命令 | 新增 `UserModules/remote_cmd`，最终调用 `Mecanum_SetVelocity()` |
| 自动导航 | 读取 `SensorSnapshot_t`，输出目标 `vx/vy/wz` |
| 任务状态机 | 放在 `UserModules/app_task`，在主循环中替换 `App_RunMotionDemo()` |
| 更多传感器 | 按 `Board_App -> Sensor_Bridge -> Control` 结构扩展，不直接让运动层读取硬件驱动 |

## 已知注意事项

| 注意点 | 说明 |
|---|---|
| 完整工程壳 | 本目录不包含 `.ioc`、启动文件和链接脚本，需要由 CubeMX 按目标芯片生成 |
| 接口命名 | 实际传感器模块使用 `Board_App_GetSensorSnapshot()`，桥接层已适配 |
| 实车标定 | 电机方向、旋转正方向和 RS485 方向脚必须实车确认 |
| 安全默认值 | 激光过近会触发急停，调车阶段建议保守保留 |
