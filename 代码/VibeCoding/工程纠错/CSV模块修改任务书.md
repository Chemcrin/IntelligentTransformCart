### CSV任务书：为物流小车 STM32 固件添加全量 CSV 调试流

#### 1. 硬件背景

- 主控：STM32F103
    
- 姿态传感器：JY61P，通过 **I2C1** 通信（地址 `0x50`，已调通）
    
- 调试输出串口：**UART1**，波特率 `115200`，8N1
    
    - 调试时通过 TTL‑USB 模块连接到 PC
        
    - 实际比赛时连接到树莓派的 UART（物理连线可互换）
        

#### 2. 功能需求

新增一个**条件编译的全量传感器数据 CSV 输出功能**，开关宏为 `CSV_DEBUG_ENABLE`（定义在 `config.h` 中）。  
当 `CSV_DEBUG_ENABLE == 1` 时：

- 每次从 JY61P 读取到一帧完整的传感器数据后，在 main 循环中**间隔发送**一行 CSV 文本到 UART1。
    
- 当 `CSV_DEBUG_ENABLE == 0` 时，**所有相关代码不占用任何 ROM/RAM/CPU 时间**。
    

#### 3. CSV 数据格式

每一行输出的字段顺序固定，均为浮点数（保留 3 位小数），英文逗号分隔，以 `\r\n` 结尾：

text

时间戳(ms), 加速度X(g), 加速度Y(g), 加速度Z(g), 角速度X(dps), 角速度Y(dps), 角速度Z(dps), Roll(°), Pitch(°), Yaw(°)

示例：

text

123456, -0.012, 0.034, 1.005, 0.23, -0.15, 0.08, 1.2, -3.4, 45.6

- 时间戳：`HAL_GetTick()` 的 32 位值。
    
- 加速度单位：g（重力加速度），需从原始寄存器值换算。
    
- 角速度单位：°/s。
    
- 姿态角单位：度，取 JY61P 融合后的角度。
    

#### 4. 输出频率与位置

- **位置**：在 main 函数的 `while(1)` 循环内，紧接在 `JY61P_ReadData()` 函数之后。
    
- **频率控制**：每进入 10 次主循环才发送一行（即 100Hz 主循环 → 10Hz CSV 输出）。  
    实现方式：静态计数器，取模10。
    

#### 5. 串口发送实现要求

- 优先使用 **HAL_UART_Transmit_DMA** 或 **HAL_UART_Transmit_IT**，避免长时间阻塞。
    
- 如果暂时使用阻塞 `printf` 也可以接受，但必须在代码注释里标记 `TODO: 改为 DMA 发送`。
    
- 需要配置 UART1 的初始化代码（`MX_USART1_UART_Init`），波特率 921600，并确保对应的 GPIO 已正确配置。
    

#### 6. 其它约束

- 格式化用的临时缓冲区长度 ≥ 128 字节，用局部数组。
    
- 不修改现有的 I2C1 驱动和主控制逻辑。
    
- 所有新增的发送代码必须放在 `#if CSV_DEBUG_ENABLE` 和 `#endif` 之间。
    
- 提交前在 `config.h` 中将 `CSV_DEBUG_ENABLE` 设置为 `1`（调试阶段默认开启）。


### 另：需要完成的细节
### 1. 创建一个条件编译开关

在全局头文件（比如 `config.h`）中加入：

```c

#define CSV_DEBUG_ENABLE  1   // 1: 开启全量CSV输出; 0: 关闭

```

所有 CSV 相关代码都用 `#if CSV_DEBUG_ENABLE` 包起来，这样比赛时一键关闭，不占任何资源。

### 2. 决定要输出的数据字段（全量）

JY61P 通过 I2C 能读到的数据通常包括（以 16 位有符号数给出）：

- 三轴加速度原始值 / 转换后的 mg 值
    
- 三轴角速度原始值 / 转换后的 °/s
    
- 三轴姿态角（Roll, Pitch, Yaw）—— 这是模块内部已融合好的
    
- 可选：温度、四元数
    

我建议的 CSV 列顺序和格式（每行一个数据帧）：

text

timestamp_ms, accelX, accelY, accelZ, gyroX, gyroY, gyroZ, roll, pitch, yaw

示例数据：

text

12345, 0.012, -0.034, 1.001, 0.23, -0.15, 0.08, 1.2, -3.4, 45.6

- `timestamp_ms` 用系统运行毫秒数（`HAL_GetTick()`），方便绘图。
    
- 数值使用**浮点**，直接保留小数点后 3~4 位，上位机可直接导入 Excel。
    
- 各列之间用逗号分隔，行末用 `\r\n`。
    

### 3. 串口输出配置

- **UART1**，波特率建议 **921600** 或 **460800**（高频率输出时 115200 可能不够快，如果控制周期 100Hz 且只输出一行约 100 字节，921600 很轻松）。
    
- 若使用 115200，则必须降低输出频率（如每 5 帧发一次）。
    
- **发送方式**：尽量用 DMA 或中断方式发送，避免 `printf` 的死等。但初期调试可直接重定向 `printf` 到 UART1，后面再优化。
    

### 4. 输出频率与触发位置

**关键：不能在每个控制周期都发送全量 CSV，否则会严重降低主控实时性。**  
必须加入分频输出逻辑，例如：

c

static uint32_t csv_counter = 0;
if (csv_counter++ % 10 == 0) {  // 每10个控制周期发一次
    SendCsvLine(&sensor_data);
}

- 如果主循环频率 100Hz，则 CSV 输出频率降为 10Hz，对人眼观察和后期分析已经足够。
    
- 将 `SendCsvLine()` 放在读取完传感器数据之后的 main 循环里，不要在中断里。
    

### 5. 缓冲区与栈保护

CSV 格式化会用到 `sprintf` 或 `snprintf`，需要较大的临时 buffer（例如 128 字节）。  
在工程设置中把堆栈大小适当增大（如 main 栈改为 2048 字节，任务栈也调大），并在代码中使用局部数组而非大量全局变量。
