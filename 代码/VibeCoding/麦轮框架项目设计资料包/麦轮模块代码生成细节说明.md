# 麦轮模块代码生成细节说明

> 本文档用于配合 `麦轮模块框架.md` 使用，重点约束后续低成本模型在生成 STM32CubeIDE + HAL + C 代码时容易写错的细节。  
> 本文档不是完整驱动实现，不允许后续模型把 `待确认` 参数擅自写死。

## 1. 文档目标

| 项目 | 说明 |
|---|---|
| 面向对象 | 后续负责补全 `.c` / `.h` 的代码生成模型 |
| 核心目标 | 避免协议、方向、单位、外设、标定参数被模型误写 |
| 适用模块 | ZDTX42 电机、RS485/Modbus、麦克纳姆轮运动学、底盘控制层 |
| 配套主文档 | `麦轮模块框架.md` |

## 2. 总体代码生成原则

| 原则 | 具体要求 |
|---|---|
| 不猜参数 | 对未实测的速度缩放、方向系数、RS485 电平、IMU yaw 方向统一保留配置宏或配置表 |
| 不改映射 | 左前 `0x01`、右前 `0x02`、左后 `0x03`、右后 `0x04` 不允许被修改 |
| 不改坐标系 | X 轴向左为正，Y 轴向前为正，Z 轴向上为正 |
| 不混单位 | 上层底盘速度用 `m/s`，角速度用 `rad/s`，ZDT 寄存器速度用 `RPM` |
| 不散落魔法数 | 机械参数、地址、寄存器、缩放系数、限幅参数必须集中到配置头文件 |
| 不在 ISR 做业务 | UART/TIM 中断只置位、搬运数据或维护计数，Modbus 状态机和运动控制放到主循环/周期任务 |
| 不并发访问总线 | 所有 ZDTX42 请求必须通过统一 Modbus 事务状态机串行化 |

| `MOTOR_ADDR_FR` | `0x02` | 是 | 右前轮固定地址 |
| `MOTOR_ADDR_RL` | `0x03` | 是 | 左后轮固定地址 |
| `MOTOR_ADDR_RR` | `0x04` | 是 | 右后轮固定地址 |

| `MECANUM_WHEEL_DIAMETER_M` | `0.075f` | 暂可使用 | 建议实车复测 |
| `MECANUM_TRACK_WIDTH_M` | `0.320f` | 暂可使用 | 建议实车复测 |
| `MECANUM_WHEEL_BASE_M` | `0.220f` | 暂可使用 | 建议实车复测 |
| `MECANUM_K_M` | `(TRACK + BASE) * 0.5f` | 是 | 由轮距和轴距计算 |
| `MECANUM_WZ_SIGN` | `待确认` | 否 | 需结合 JY61P yaw 正方向确认 |

| `RPM_LIMIT` | `500` 起步 | 可调 | 需结合实车稳定性 |
| `ACC_LIMIT_RPM_S` | `2000` 起步 | 可调 | 防止加速度突变 |

## 4. 速度缩放系数：`ZDT_SPEED_MODE_SCALE`

### 4.1 问题来源

| 项目 | 说明 |
|---|---|
| 已知资料 | ZDT 速度模式 `0x00E6` 的 Reg3 标注为速度，单位 `RPM` |
| 疑点 | 同一份资料在位置模式中出现“速度和位置角度放大 10 倍”的描述，但速度模式表没有明确说要放大 10 倍 |
| 处理原则 | 默认按整数 RPM，即 `ZDT_SPEED_MODE_SCALE = 1.0f`，但必须实测确认 |

### 4.2 代码生成要求

| 要求 | 说明 |
|---|---|
| 必须保留缩放宏 | 不能直接写 `speed_reg = rpm` 或 `speed_reg = rpm * 10` |
| 必须集中使用 | 所有速度命令寄存器写入都经过同一个转换函数 |
| 必须防溢出 | `speed_reg` 限制在 `0..0xFFFF` |
| 必须保留注释 | 注明 `1` 与 `10` 的差异来自 ZDT 资料表述不一致 |

推荐转换逻辑：

```text
speed_abs_rpm = abs(rpm_motor)
speed_reg = round(speed_abs_rpm * ZDT_SPEED_MODE_SCALE)
speed_reg = clamp(speed_reg, 0, 0xFFFF)
```

### 4.3 标定方法

| 步骤 | 操作 | 判断 |
|---|---|---|
| 1 | 只连接地址 `0x01` 的单个电机 | 排除总线和轮系干扰 |
| 2 | 设置 `ZDT_SPEED_MODE_SCALE = 1.0f` | 先按资料速度模式 `RPM` 处理 |
| 3 | 下发 `60 RPM`、`120 RPM`、`300 RPM` | 每个速度保持数秒 |
| 4 | 读取 `0x0044` 实时转速并观察实际转速 | 反馈与实际接近目标则保持 `1.0f` |
| 5 | 若实际速度约差 10 倍 | 改为 `10.0f` 并复测 |

## 5. 反馈缩放系数：`ZDT_SPEED_FEEDBACK_SCALE`

| 项目 | 说明 |
|---|---|
| 来源寄存器 | `0x0044`，读取实时转速 |
| 资料描述 | Reg1 为符号，Reg2 为转速绝对值，标注单位为 RPM |
| 疑点 | 若驱动固件返回值按 0.1 RPM 编码，则需要除以 10 |

代码生成要求：

```text
sign = (sign_reg == 0) ? +1 : -1
rpm_fb = sign * rpm_raw / ZDT_SPEED_FEEDBACK_SCALE
```

| 注意项 | 处理 |
|---|---|
| `sign_reg` 只能为 `0` 或 `1` | 其他值判为响应异常 |
| `rpm_raw` 超过限制 | 丢弃或标记异常 |
| 连续读取失败 | 不更新反馈值，超时计数累加 |
| scale 未确认 | 默认 `1.0f`，但调试报告必须记录结果 |

## 6. 每轮方向系数：`motor_dir_sign[4]`

### 6.1 作用

`motor_dir_sign[4]` 是每个轮子的电机方向修正表，用于把“运动学正轮速”转换为 ZDT 驱动器的 CW/CCW。

| 索引 | 轮位 | 地址 | 含义 |
|---:|---|---:|---|
| `0` | FL 左前 | `0x01` | 左前方向修正 |
| `1` | FR 右前 | `0x02` | 右前方向修正 |
| `2` | RL 左后 | `0x03` | 左后方向修正 |
| `3` | RR 右后 | `0x04` | 右后方向修正 |

### 6.2 代码生成要求

| 要求 | 说明 |
|---|---|
| 数组顺序固定 | 必须为 `FL, FR, RL, RR` |
| 地址映射固定 | 不允许通过修改地址来修方向 |
| 默认值不可假装已确认 | 可暂设 `{+1,+1,+1,+1}` 作为编译默认，但注释必须标明“实车待标定” |
| 转换集中封装 | 不允许在多个文件里手写方向判断 |

推荐转换逻辑：

```text
rpm_motor = rpm_kinematics * motor_dir_sign[index]

if rpm_motor >= 0:
    zdt_dir = CW
else:
    zdt_dir = CCW

speed_reg = abs(rpm_motor) * ZDT_SPEED_MODE_SCALE
```

### 6.3 标定方法

| 步骤 | 操作 | 记录 |
|---|---|---|
| 1 | 架空底盘或让车轮离地 | 保证安全 |
| 2 | 单独控制 `0x01` 低速 CW | 观察左前轮方向 |
| 3 | 判断是否符合“运动学正轮速”定义 | 符合记 `+1`，相反记 `-1` |
| 4 | 依次测试 `0x02`、`0x03`、`0x04` | 得到完整数组 |
| 5 | 执行前进、左移、旋转基础动作 | 验证四轮方向组合正确 |

## 7. RS485 方向控制有效电平

### 7.1 为什么要确认

RS485 半双工同一时刻只能发送或接收。STM32 需要通过 GPIO 控制收发器方向，常见接法是 `DE` 与 `/RE` 短接。

| GPIO 电平 | 常见含义 | 但是否一定成立 |
|---:|---|---|
| 高电平 | TX，发送使能 | 不一定，取决于模块接法 |
| 低电平 | RX，接收使能 | 不一定，取决于模块接法 |

### 7.2 代码生成要求

| 要求 | 说明 |
|---|---|
| 必须用宏封装 | 使用 `RS485_TX_ENABLE()`、`RS485_RX_ENABLE()` |
| 不要散写 GPIO 电平 | 不能在代码中到处写 `GPIO_PIN_SET/RESET` |
| 初始状态必须 RX | 初始化后默认切到接收态 |
| 发送后等 TC | 必须等待 UART 发送完成标志 `TC` 后再切回 RX |
| 广播不等响应 | 地址 `0x00` 广播帧发送后直接完成 |

推荐流程：

```text
RS485_RX_ENABLE()
清空 RX 缓冲
RS485_TX_ENABLE()
短延时 t_DE_ON
UART 发送帧
等待 UART TC
短延时 1 字符时间，按实测可选
RS485_RX_ENABLE()
若单播：等待响应
若广播：不等待响应
```

### 7.3 标定方法

| 步骤 | 操作 | 判断 |
|---|---|---|
| 1 | 默认假设高电平 TX、低电平 RX | 常见 RS485 模块接法 |
| 2 | 发送读转速命令 | 若能收到响应，电平定义成立 |
| 3 | 若一直超时 | 反转 TX/RX 电平定义再测 |
| 4 | 用逻辑分析仪观察 TXD、RXD、A/B | 最可靠 |
| 5 | 若发送后有波形但无回复 | 检查 A/B、终端电阻、共地、驱动器地址 |

## 8. 角速度方向：`MECANUM_WZ_SIGN` 与 JY61P yaw

### 8.1 问题说明

本文坐标系定义 Z 轴向上，但 JY61P 的 yaw 增减方向取决于模块安装方向和内部坐标定义。若符号错误，航向闭环会变成正反馈。

| 参数 | 含义 |
|---|---|
| `wz_radps` | 上层要求的绕 Z 轴角速度 |
| `MECANUM_WZ_SIGN` | 旋转符号修正系数，取 `+1` 或 `-1` |
| `wz_eff_radps` | 进入运动学公式的有效角速度 |

推荐关系：

```text
wz_eff_radps = MECANUM_WZ_SIGN * wz_radps
```

### 8.2 代码生成要求

| 要求 | 说明 |
|---|---|
| 不直接改公式 | 通过 `MECANUM_WZ_SIGN` 修正旋转方向 |
| yaw 单位必须 rad | 通过 `JY61P_GetYawRad()` 获取 |
| 角速度单位必须 rad/s | 通过 `JY61P_GetGyroZRadS()` 获取 |
| 航向误差必须 wrap | 使用 `wrap_to_pi()`，避免 359° 到 1° 误判 |
| 闭环先低速测试 | 防止符号错误导致越修越偏 |

### 8.3 标定方法

| 步骤 | 操作 | 判断 |
|---|---|---|
| 1 | 小车静止，读取 `yaw_rad` |
| 2 | 从车顶往下看，手动逆时针旋转小车 | 观察 yaw 增减 |
| 3 | 若 yaw 增大 | IMU yaw 正方向为逆时针 |
| 4 | 若 yaw 减小 | IMU yaw 正方向为顺时针 |
| 5 | 下发 `Mecanum_Rotate(+0.3f)` | 实车旋转方向应与软件定义一致 |
| 6 | 若旋转命令方向相反 | 调整 `MECANUM_WZ_SIGN`，不改轮位地址 |

## 9. UART 口径冲突处理

| 资料位置 | 出现口径 | 处理 |
|---|---|---|
| 框架设计要求 | `UART3/PB10/PB11` | 本轮最终采用 |
| 硬件手册部分章节 | `USART1/PA9/PA10` | 旧口径，不能直接照搬 |
| 设计文档部分章节 | `USART2/PA2/PA3` | 旧口径，不能直接照搬 |
| 树莓派链路 | `USART2/PA2/PA3` | 保留给树莓派/CH340N 通信 |

后续代码生成要求：

| 项目 | 要求 |
|---|---|
| 电机通信 UART 句柄 | 优先使用 `huart3` |
| 电机通信引脚 | `PB10` TX、`PB11` RX |
| 树莓派通信 | 不要占用 `UART3`，继续按上层通信链路规划 |
| 变量总览旧内容 | 需要同步更新，不能让低成本模型误用 `USART1` 或 `USART2` 控电机 |

## 10. Modbus 帧与寄存器细节

| 项目 | 代码生成要求 |
|---|---|
| CRC | 使用统一 `Modbus_CRC16()`，禁止硬编码 CRC |
| CRC 顺序 | 帧尾发送 `CRC_L` 再 `CRC_H` |
| 功能码 | 读输入寄存器 `0x04`，写单寄存器 `0x06`，写多个寄存器 `0x10` |
| 速度控制 | 使用 `0x10` 写 `0x00E6` 起始的 4 个寄存器 |
| 速度反馈 | 使用 `0x04` 读 `0x0044` 起始的 2 个寄存器 |
| 使能 | 使用 `0x10` 写 `0x00E0` 起始的 2 个寄存器 |
| 急停 | 使用 `0x10` 写 `0x00FE` 的立即停止命令 |
| 同步触发 | 广播地址 `0x00` 写 `0x00FF=0x6600` |
| 异常响应 | 若功能码 `function | 0x80`，进入 Modbus 异常处理 |

禁止事项：

| 禁止项 | 原因 |
|---|---|
| 禁止手写示例帧作为实际发送帧 | CRC、地址、速度、方向都应动态生成 |
| 禁止广播后等待响应 | Modbus 广播没有从站响应 |
| 禁止多个模块直接调用 UART 发送 | 会造成 RS485 总线冲突 |
| 禁止忽略响应地址 | 可能把错误电机响应当成正确响应 |

## 11. 运动学变量命名与单位细节

| 变量 | 含义 | 单位 | 正方向 |
|---|---|---|---|
| `vx_mps` | 横向速度 | `m/s` | 向左为正 |
| `vy_mps` | 纵向速度 | `m/s` | 向前为正 |
| `wz_radps` | 绕 Z 轴角速度 | `rad/s` | 由 `MECANUM_WZ_SIGN` 标定 |
| `wheel_fl_mps` | 左前轮线速度 | `m/s` | 运动学正轮速 |
| `wheel_fr_mps` | 右前轮线速度 | `m/s` | 运动学正轮速 |
| `wheel_rl_mps` | 左后轮线速度 | `m/s` | 运动学正轮速 |
| `wheel_rr_mps` | 右后轮线速度 | `m/s` | 运动学正轮速 |
| `wheel_rpm[4]` | 四轮有符号 RPM | `RPM` | `FL,FR,RL,RR` |

特别注意：

| 易错点 | 正确处理 |
|---|---|
| 旧设计文档中 `v_x` 表示前向 | 本文代码接口用 `vy_mps` 表示前向 |
| 旧设计文档中 `v_y` 表示左向 | 本文代码接口用 `vx_mps` 表示左向 |
| `omega` 与 `wz_radps` 混用 | 对外统一使用 `wz_radps` |
| `speed_mps` 直接写入 ZDT | 错误，必须先转 RPM，再转方向和寄存器值 |

## 12. 状态机与安全细节

| 状态 | 代码生成注意事项 |
|---|---|
| `IDLE` | 不下发非零速度 |
| `READY` | 电机在线、传感器状态满足要求后进入 |
| `RUNNING` | 周期性刷新速度命令，检查安全条件 |
| `STOP` | 发送四轮 0 速度同步命令 |
| `FAULT` | 禁止普通运动命令，允许查询和复位流程 |
| `EMERGENCY_STOP` | 急停后必须显式解除，不允许自动恢复运动 |

安全触发优先级：

| 优先级 | 条件 | 动作 |
|---:|---|---|
| P0 | 外部急停、严重电机故障、姿态异常严重、障碍物过近且仍向障碍物运动 | 立即急停 |
| P1 | 连续通信超时、CRC 错误频繁、电机离线 | 减速停机并进入故障 |
| P2 | 上层命令超时、传感器短暂无效 | 保持或降速，等待恢复 |

## 13. 测试驱动代码生成要求

后续模型生成代码时，必须提供或预留以下测试入口：

| 测试入口 | 用途 | 要求 |
|---|---|---|
| `ZDTX42_TestSingleMotor(addr, rpm)` | 单电机速度测试 | 只控制一个地址 |
| `ZDTX42_TestReadSpeed(addr)` | 读取实时转速 | 打印或返回 RPM |
| `Mecanum_TestMotorDirection()` | 四轮方向标定 | 逐轮低速点动 |
| `Mecanum_TestMoveForward(speed_mps)` | 前进测试 | 验证四轮同向 |
| `Mecanum_TestMoveLeft(speed_mps)` | 左移测试 | 验证 FL/RR 与 FR/RL 符号关系 |
| `Mecanum_TestRotate(wz_radps)` | 原地旋转测试 | 验证 `MECANUM_WZ_SIGN` |
| `RS485_TestDirectionLevel()` | RS485 收发方向测试 | 用读转速命令确认 TX/RX 电平 |

测试顺序必须固定：

```text
1. RS485 物理通信
2. 单电机读转速
3. 单电机速度缩放
4. 四电机地址扫描
5. 每轮方向系数标定
6. 四轮同步触发
7. 前进/后退/左移/右移/旋转
8. IMU yaw 符号与航向闭环
9. 激光减速/停车
10. 异常和急停
```

## 15. 给后续代码生成模型的硬性提醒

| 编号 | 提醒 |
|---|---|
| R1 | 看到 `待确认` 时，不要脑补成确定值；必须保留宏、注释和测试入口 |
| R2 | 电机链路使用 `UART3/PB10/PB11`，不要照搬旧文档的 `USART1` 或 `USART2` |
| R3 | `vx_mps` 是左向速度，`vy_mps` 是前向速度，不要按旧文档变量含义写反 |
| R4 | 四轮数组顺序固定为 `FL,FR,RL,RR` |
| R5 | 四轮地址映射固定为 `0x01,0x02,0x03,0x04` |
| R6 | 所有 Modbus CRC 必须运行时计算 |
| R7 | 广播地址 `0x00` 不等待响应 |
| R8 | 默认不做高速主控轮速 PID，只保留低频监督 PI 的扩展口 |
| R9 | 急停状态不能自动恢复，必须有显式解除流程 |
| R10 | 生成代码后必须提供逐步测试说明，不能直接进入整车联调 |
