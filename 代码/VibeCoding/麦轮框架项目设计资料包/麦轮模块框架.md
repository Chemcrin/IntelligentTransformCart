# 麦轮模块框架.md

## 1. 模块目标

| 项目 | 说明 |
|---|---|
| 模块名称 | ZDTX42 电机与麦克纳姆轮组控制模块 |
| 运行平台 | `STM32F103C8T6` + `STM32CubeIDE` + `STM32 HAL` + C 语言 |
| 控制对象 | 4 个 ZDT_X42 闭环步进电机与 X 型麦克纳姆轮底盘 |
| 对外功能 | 接收底盘速度向量、基础运动命令、停止/急停命令；输出电机命令、状态与故障信息 |
| 功能边界 | 负责底盘运动学、四轮速度分配、ZDTX42 通信封装、速度限幅、同步下发、异常保护 |
| 不负责内容 | 不直接实现视觉识别、路径规划、完整传感器驱动、树莓派上层协议、完整 `.c/.h` 业务代码 |

## 2. 硬件连接关系

| 硬件链路 | 规划连接 | 说明 |
|---|---|---|
| STM32 与电机驱动 | `UART3_TX/PB10`、`UART3_RX/PB11` → RS485 模块 → 4 个 ZDT_X42 | 本文按最新框架要求固化为 UART3。 |
| RS485 总线 | 半双工，一主多从 | STM32 为 Modbus 主站，4 个电机为从站。 |
| RS485 方向控制 | `RS485_DIR_GPIO_Port` + `RS485_DIR_Pin` | 具体 GPIO 与有效电平 `待确认`。 |
| 树莓派链路 | 树莓派 4B → CH340N → STM32 `USART2/PA2/PA3` | 用于速度命令、任务状态、状态回传。 |
| 传感器链路 | `I2C1/PB6/PB7` → JY61P、ATK-MS53L1M | 麦轮模块通过桥接 API 使用传感器数据，不直接占用 I2C。 |
| 供电 | 12V 母线供电机驱动，TPS5450 转 5V 供树莓派、CH340N、STM32 | ZDT_X42 x4 功耗 `待确认`，需实测。 |

| CubeMX / HAL 项 | 建议配置 |
|---|---|
| `USART3` | Asynchronous，`115200 8N1` 起步，TX/RX，接收中断或 DMA |
| `GPIO` | RS485 方向控制脚，默认 RX 状态 |
| `TIM` | 1 ms tick；20 ms 主控制周期可由软件分频得到 |
| `I2C1` | 由传感器模块使用，麦轮模块只通过桥接接口读取数据 |
| `SWD` | 保持开启，便于实车调试 |

> 注意：旧资料中出现 `USART1/PA9/PA10` 与 `USART2/PA2/PA3` 作为电机链路的口径。后续低成本模型生成代码时必须按本文 `UART3/PB10/PB11` 规划，除非用户明确修改硬件方案。

## 3. 电机地址与轮位映射

```text
Y 车头方向

左前轮 FL    右前轮 FR
0x01         0x02

左后轮 RL    右后轮 RR
0x03         0x04
```

| 轮位 | 电机地址宏 | 地址值 | 约束 |
|---|---|---:|---|
| 左前轮 FL | `MOTOR_ADDR_FL` | `0x01` | 固定映射，不允许修改 |
| 右前轮 FR | `MOTOR_ADDR_FR` | `0x02` | 固定映射，不允许修改 |
| 左后轮 RL | `MOTOR_ADDR_RL` | `0x03` | 固定映射，不允许修改 |
| 右后轮 RR | `MOTOR_ADDR_RR` | `0x04` | 固定映射，不允许修改 |
| 广播地址 | `MOTOR_ADDR_BROAD` | `0x00` | 仅用于广播同步触发或广播急停，不等待响应 |

## 4. 坐标系与运动方向定义

| 变量 | 正方向 | 单位 | 说明 |
|---|---|---|---|
| `vx_mps` | 小车左侧 | `m/s` | X 轴横移速度，向左为正 |
| `vy_mps` | 小车正前方 | `m/s` | Y 轴纵向速度，向前为正 |
| `wz_radps` | 绕 Z 轴旋转 | `rad/s` | 正方向需结合 JY61P yaw 与实车方向验证，标注为 `待确认` |

| 兼容注意 | 处理方式 |
|---|---|
| 旧设计文档中 `v_x` 表示前向、`v_y` 表示左向 | 本文不沿用旧变量含义，统一使用 `vx_mps=左向`、`vy_mps=前向` |
| 变量总览已有 `ChassisVel_t.vx/vy/omega` | 若继续使用该结构体，必须在注释中明确 `vx=左向`、`vy=前向`；否则建议新增带单位后缀的结构体 |
| IMU yaw 正方向 | 通过 `JY61P_GetYawRad()` 获取，和 `wz_radps` 的正方向关系 `待确认` |

## 5. 麦轮安装方式

| 项目 | 约束 |
|---|---|
| 安装形态 | X 型交叉状 |
| 纹路关系 | 斜对角线方向上的麦轮纹路方向相同 |
| 运动学影响 | 横移与旋转项的符号必须按 X 型麦轮公式规划 |
| 调试约束 | 方向不一致时，只能调整每轮方向系数或检查安装，不得修改地址映射 |

建议为每个电机保留方向修正系数：

| 配置项 | 含义 | 取值 | 来源 |
|---|---|---|---|
| `motor_dir_sign[0]` | FL 运动学正轮速对应驱动方向 | `+1` 或 `-1` | 实车点动标定 |
| `motor_dir_sign[1]` | FR 运动学正轮速对应驱动方向 | `+1` 或 `-1` | 实车点动标定 |
| `motor_dir_sign[2]` | RL 运动学正轮速对应驱动方向 | `+1` 或 `-1` | 实车点动标定 |
| `motor_dir_sign[3]` | RR 运动学正轮速对应驱动方向 | `+1` 或 `-1` | 实车点动标定 |

## 6. 软件分层设计

| 层级 | 建议模块 | 职责 | 禁止事项 |
|---|---|---|---|
| 上层接口层 | `mecanum.h` / `mecanum.c` | 提供 `Mecanum_Init()`、`Mecanum_SetVelocity()`、`Mecanum_Stop()` 等接口 | 不直接拼 Modbus 字节 |
| 底盘控制层 | `chassis_control.h` / `chassis_control.c` | 状态机、速度限幅、航向保持、激光限速、安全状态 | 不直接操作 UART |
| 运动解算层 | `mecanum_kinematics.h` / `mecanum_kinematics.c` | `vx_mps/vy_mps/wz_radps` 与四轮速度互转 | 不关心电机地址和 RS485 |
| 电机管理层 | `motor_manager.h` / `motor_manager.c` | 四轮命令缓存、方向修正、同步下发、反馈状态聚合 | 不编造协议字节 |
| ZDTX42 驱动层 | `zdt_x42_modbus.h` / `zdt_x42_modbus.c` | 封装 ZDTX42 使能、速度、停止、读取转速等寄存器级命令 | 不做底盘运动学 |
| Modbus 通信层 | `modbus_rtu.h` / `modbus_rtu.c` | CRC16、帧组装、发送接收、事务状态机、超时处理 | 不包含业务策略 |
| HAL 适配层 | CubeMX 生成代码与 `main.c` | 初始化 UART3、GPIO、TIM、中断/DMA | 不在中断里做复杂控制 |

推荐调用方向：

```text
路径规划/主控逻辑
  -> Mecanum_SetVelocity(vx_mps, vy_mps, wz_radps)
  -> 运动学解算四轮速度
  -> motor_manager 做限幅、方向修正、同步策略
  -> zdt_x42_modbus 生成寄存器级命令
  -> modbus_rtu 通过 UART3 + RS485 发送
```

| 类型 | 规则 |
|---|---|
| 全局变量 | 使用 `g_` 前缀，例如 `g_mecanum_state`、`g_motor_rpm_fb[4]` |

## 11. 麦轮运动学模型

### 11.1 变量定义

| 变量 | 含义 |
|---|---|
| `vx_mps` | 车体 X 轴速度，向左为正 |
| `vy_mps` | 车体 Y 轴速度，向前为正 |
| `wz_radps` | 绕 Z 轴角速度，正方向 `待确认` |
| `wz_eff_radps` | 进入运动学公式的有效角速度，`wz_eff_radps = MECANUM_WZ_SIGN * wz_radps` |
| `K` | 旋转耦合臂长，`K=(L+W)/2` |

### 11.2 逆运动学关系

基于 X 型麦克纳姆轮与本文坐标系，推荐先采用以下符号关系，再通过实车验证 `MECANUM_WZ_SIGN` 与 `motor_dir_sign[4]`：

```text
wheel_fl_mps = vy_mps - vx_mps - K * wz_eff_radps
wheel_fr_mps = vy_mps + vx_mps + K * wz_eff_radps
wheel_rl_mps = vy_mps + vx_mps - K * wz_eff_radps
wheel_rr_mps = vy_mps - vx_mps + K * wz_eff_radps
```

轮线速度到 RPM：

```text
wheel_rpm = wheel_mps / (π * MECANUM_WHEEL_DIAMETER_M) * 60
```

### 11.3 典型动作符号检查

| 期望动作 | 输入 | 理论轮速关系 |
|---|---|---|
| 前进 | `vx_mps=0`，`vy_mps>0`，`wz=0` | 四轮同号同速 |
| 后退 | `vx_mps=0`，`vy_mps<0`，`wz=0` | 四轮同号反向 |
| 左移 | `vx_mps>0`，`vy_mps=0`，`wz=0` | FL、RR 为负；FR、RL 为正 |
| 右移 | `vx_mps<0`，`vy_mps=0`，`wz=0` | FL、RR 为正；FR、RL 为负 |
| 原地旋转 | `vx=0`，`vy=0`，`wz_eff>0` | FL、RL 为负；FR、RR 为正 |
| 斜向移动 | `vx` 与 `vy` 同时非零 | 四轮为前进与横移叠加结果，部分轮速可接近 0 |

### 11.4 正运动学与里程计

正运动学用于速度反馈、里程计和故障诊断。若读取四轮实际 RPM，需要先按 `ZDT_SPEED_FEEDBACK_SCALE` 转换为有效 RPM，再转为轮线速度。

```text
vy_est_mps   = ( wheel_fl_mps + wheel_fr_mps + wheel_rl_mps + wheel_rr_mps ) / 4
vx_est_mps   = (-wheel_fl_mps + wheel_fr_mps + wheel_rl_mps - wheel_rr_mps ) / 4
wz_est_radps = (-wheel_fl_mps + wheel_fr_mps - wheel_rl_mps + wheel_rr_mps ) / (4 * K)
```

里程计积分时建议使用 `JY61P_GetYawRad()` 提供的航向角替代纯轮速积分角度，降低麦轮打滑造成的航向漂移。

## 12. ZDTX42 通信协议封装思路

### 12.1 Modbus-RTU 基本规则

| 项目 | 规则 |
|---|---|
| 帧结构 | 从机地址 + 功能码 + 数据区 + CRC16 |
| CRC | Modbus CRC16，多项式 `0xA001`，初值 `0xFFFF` |
| CRC 发送顺序 | `CRC_L` 在前，`CRC_H` 在后 |
| 寄存器字节序 | 16 bit 寄存器高字节在前 |
| 32 bit 数据 | 资料说明低字在前、高字在后，速度模式主要使用 16 bit |
| 广播地址 | `0x00`，广播命令不等待响应 |

### 12.2 已确认寄存器与功能码

| 功能 | 功能码 | 起始寄存器 | 数量 | 数据 / 说明 |
|---|---:|---:|---:|---|
| 读取实时转速 | `0x04` | `0x0044` | `0x0002` | Reg1 符号，Reg2 转速绝对值 |
| 速度模式控制 | `0x10` | `0x00E6` | `0x0004` | 方向、加速度、速度、同步标志 |
| 电机使能 | `0x10` | `0x00E0` | `0x0002` | Reg1=`0xAB01/0xAB00`，Reg2 同步标志 |
| 立即停止 | `0x10` | `0x00FE` | `0x0001` | `0x9800` |
| 多机同步触发 | `0x10` | `0x00FF` | `0x0001` | `0x6600` |
| 修改地址 | `0x10` | `0x00A2` | `0x0002` | 仅调试/配置阶段使用 |

### 12.3 速度命令封装

速度模式写 `0x00E6`，4 个寄存器含义如下：

| 寄存器 | 含义 | 值域 / 说明 |
|---|---|---|
| Reg1 | 方向 | `0x0000` = CW，`0x0001` = CCW |
| Reg2 | 加速度 | `RPM/s`，`uint16_t` |
| Reg3 | 速度 | `RPM`，非负 `uint16_t`，缩放系数 `待确认` |
| Reg4 | 同步标志 | `0x0000` 立即执行；`0x0100` 缓存等待广播触发 |

单轮 RPM 转 ZDT 命令逻辑：

```text
1. rpm_signed 来自运动学和限幅层。
2. rpm_motor = rpm_signed * motor_dir_sign[index]。
3. rpm_motor >= 0 时使用 CW，否则使用 CCW。
4. speed_reg = round(abs(rpm_motor) * ZDT_SPEED_MODE_SCALE)。
5. speed_reg 限制到 0..0xFFFF。
```

### 12.4 四轮同步策略

| 策略 | 说明 | 默认建议 |
|---|---|---|
| 连续单播立即生效 | 依次给 1-4 号电机写速度，`Reg4=0x0000` | 可用于低速巡航或调试 |
| 单播缓存 + 广播同步触发 | 先给 1-4 号写缓存速度，`Reg4=0x0100`，再广播写 `0x00FF=0x6600` | 默认采用 |

同步流程：

```text
1. 写 FL/0x01 速度缓存，等待响应。
2. 写 FR/0x02 速度缓存，等待响应。
3. 写 RL/0x03 速度缓存，等待响应。
4. 写 RR/0x04 速度缓存，等待响应。
5. 广播地址 0x00 写同步触发寄存器 0x00FF，数据 0x6600。
6. 广播帧不等待响应。
```

### 12.5 RS485 半双工事务

| 步骤 | 动作 |
|---|---|
| 1 | 确认 Modbus 状态机空闲，清理旧 RX 缓冲 |
| 2 | 组帧并计算 CRC |
| 3 | `RS485_DIR` 切到 TX，等待收发器稳定 |
| 4 | 通过 `HAL_UART_Transmit`、中断或 DMA 发送 |
| 5 | 等待 UART `TC`，确保最后一位已发送完成 |
| 6 | `RS485_DIR` 切回 RX |
| 7 | 单播等待响应并校验，广播直接完成 |
| 8 | 超时、CRC 错、异常功能码统一进入错误处理 |

## 13. 控制流程

### 13.1 初始化流程

```text
1. HAL 初始化、系统时钟初始化。
2. CubeMX 初始化 GPIO、UART3、TIM、I2C1、USART2。
3. RS485_DIR 默认置为 RX。
4. 初始化 Modbus 事务状态机和 ZDTX42 驱动层。
5. 初始化麦轮配置、方向系数默认值、速度限幅参数。
6. 扫描 0x01-0x04，读取一次转速或状态。
7. 对 4 个电机执行使能。
8. 下发四轮 0 速度并广播同步触发。
9. 检查 IMU/激光桥接数据是否有效。
10. 状态进入 READY；若任一关键项失败，进入 FAULT。
```

### 13.2 速度控制流程

```text
1. 上层调用 Mecanum_SetVelocity(vx_mps, vy_mps, wz_radps)。
2. 安全层检查急停、姿态异常、激光过近、命令超时。
3. 对 vx/vy/wz 做限幅与斜率限制。
4. 可选：利用 JY61P 航向闭环修正 wz。
5. 可选：利用激光距离修正 vx/vy 或触发减速。
6. 调用逆运动学计算四轮 wheel_*_mps。
7. 转换为四轮目标 RPM。
8. 做四轮等比例限幅与每轮方向系数修正。
9. 生成 4 个 ZDTX42 速度缓存命令。
10. 广播同步触发。
11. 更新目标速度缓存和状态。
```

### 13.3 停止与急停流程

| 场景   | 流程                                                          |
| ---- | ----------------------------------------------------------- |
| 正常停止 | 四轮目标速度置 0 → 同步缓存 → 广播同步触发 → 等待反馈接近 0                        |
| 急停   | 广播立即停止 `0x00FE=0x9800` 或四轮 0 速度紧急下发 → 状态进入 `EMERGENCY_STOP` |
| 故障停机 | 先减速停机；若故障严重或持续超时，升级为急停                                      |

## 15. 异常与保护机制

| 异常 | 检测方式 | 处理策略 |
|---|---|---|
| 单电机通信超时 | `ZDTX42_ReceiveFrame()` 超时计数 | 单次保持旧值；连续 3 次进入减速停机或故障 |
| CRC 错误 | `ZDTX42_CheckFrame()` | 丢弃响应，错误计数累加，频繁错误降低总线频率并检查 A/B |
| 地址冲突 | 多电机同时响应、CRC 异常、随机超时 | 断开总线，逐台上电重新设置地址 |
| RS485 方向切换错误 | 发送后无响应或响应截断 | 等待 UART TC 后再切 RX，检查 `RS485_DIR` 极性 |
| 电机无响应 | 读速度/状态失败 | 标记离线，停止整车输出 |
| 电机故障状态 | 读系统状态参数 `0x0078`，字段含义按资料解析 | 进入 FAULT 或 EMERGENCY_STOP |
| 超速 | 目标 RPM 超过 `RPM_LIMIT` | 等比例缩放四轮 RPM |
| 加速度过大 | 目标变化超过 `ACC_LIMIT_RPM_S` | 斜率限制 |
| 姿态异常 | Roll/Pitch 超阈值 | 减速停机或急停 |
| 激光过近 | `Laser_GetWarningLevel()` 达停车等级 | 禁止继续向障碍物方向运动，必要时急停 |
| 方向错误 | 基础动作测试方向与理论不一致 | 调整 `motor_dir_sign[4]` 或检查安装，不改地址 |
| 上层命令超时 | 树莓派心跳或命令序号超时 | 进入安全停车 |

## 16. 调试与测试计划

| 阶段 | 测试目标 | 必测项 | 通过标准 |
|---|---|---|---|
| 1. 单电机通信测试 | 确认 UART3 + RS485 + 单个 ZDTX42 可通信 | 单独连接 `0x01`，读 `0x0044`，使能，低速正反转，停止 | 无超时、CRC 正确、可控制启停 |
| 2. 单电机参数测试 | 确认速度缩放与反馈缩放 | 下发 60/120/300 RPM，读取反馈并观察实际转速 | 确定 `ZDT_SPEED_MODE_SCALE` 与 `ZDT_SPEED_FEEDBACK_SCALE` |
| 3. 四电机寻址测试 | 确认地址与轮位一致 | 逐台设置并读取 `0x01`-`0x04` | 地址唯一，轮位与表一致 |
| 4. 四轮方向测试 | 标定每轮方向 | 逐轮低速点动，记录实际正转方向与纹路 | 得到正确 `motor_dir_sign[4]` |
| 5. 同步启动测试 | 验证缓存 + 广播同步 | 四轮写缓存速度，再广播 `0x00FF=0x6600` | 起步/停止无明显轮间延迟 |
| 6. 基础动作测试 | 验证运动学符号 | 前进、后退、左移、右移、停止、原地旋转 | 方向符合理论关系 |
| 7. 组合动作测试 | 验证速度叠加 | 斜向移动、边平移边旋转、速度阶跃变化 | 无异常抖动，限幅生效 |
| 8. 传感器闭环测试 | 验证航向和距离修正 | JY61P 航向保持、激光减速、过近停车 | 修正方向正确，误停率可接受 |
| 9. 异常测试 | 验证保护机制 | 拔掉 RS485、断开单电机、CRC 错误、急停、超速、单轮方向错误 | 进入预期故障或急停状态 |

测试注意：

| 规则 | 说明 |
|---|---|
| 地址不改 | 测试失败时不得修改 `0x01/0x02/0x03/0x04` 固定映射 |
| 公式不乱改 | 若方向不一致，优先调 `motor_dir_sign[4]`、`MECANUM_WZ_SIGN` 或检查安装 |
| 低速起步 | 首轮测试从低速、低加速度开始 |
| 单项闭环 | 先不开启轮速 PI，只跑驱动器内部闭环；确认稳定后再启用低频监督 PI |
| 记录参数 | 每次修改缩放、方向系数、限幅参数都要记录来源和测试结果 |
