## 1. 总体结论

该工程是一个基于 `STM32F103C8T6` 的麦克纳姆轮小车控制工程。当前主程序运行的是一个固定时间片的开环运动 Demo：前进、后退、左移、右移、原地旋转，然后停止。工程同时接入了 I2C IMU 和 I2C 激光测距模块，其中激光测距被用于急停保护，IMU 目前只采集和发布姿态数据，未参与路径闭环。

| 维度 | 当前状态 | 说明 |
| --- | --- | --- |
| 底盘控制 | 已实现 | `Mecanum -> ChassisControl -> MotorManager -> ZDTX42 -> Modbus RTU` |
| 路径控制 | 开环 Demo | 按 `HAL_GetTick()` 时间切换动作，没有任务状态机、里程计或闭环导航 |
| 避障/急停 | 已实现基础逻辑 | 激光无效或距离过近时触发外部急停 |
| IMU 使用 | 已采集，未闭环 | 采集 yaw/pitch/roll/gyro/acc，但主路径未使用 yaw 修正 |
| 电机通信 | 设计为 RS485/Modbus | 使用 `USART3`，4 个 ZDT X42 电机驱动地址为 `0x01~0x04` |
| 可编译性 | 当前存在明显风险 | 缺少 `i2c.h/usart.h/gpio.h` 与 VL53L1 API 文件 |

## 5. 当前小车实际运行路径

### 5.1 触发前提

主循环每 10 ms 调用一次传感器刷新，然后读取 `Sensor_GetSnapshot()`。路径 Demo 只有在以下条件同时满足时才会运行：

| 条件 | 代码行为 |
| --- | --- |
| `snap.laser_valid == true` | 激光在线且数据未超时 |
| `snap.laser_warning < 3` | 未达到 too_close 急停级别 |
| 底盘未处于 FAULT | `ChassisControl_SetVelocity()` 才能接受新速度 |

如果激光无效、未连接、初始化失败或距离过近，主循环会执行 `ChassisControl_SetExternalEmergency(1U)`，底盘进入急停，实际路径为“不运动或立即停止”。

### 5.2 固定时间片路径

在激光有效且前方安全的情况下，`App_RunMotionDemo()` 从 `demo_start_ms` 开始按绝对时间执行以下动作：

| 时间段 | 指令 | 目标速度 | 理想位移/角度 |
| --- | --- | --- | --- |
| `0~3 s` | 前进 | `vy = +0.12 m/s` | 向前约 `0.36 m` |
| `3~5 s` | 停止 | `0` | 原地等待 `2 s` |
| `5~8 s` | 后退 | `vy = -0.12 m/s` | 向后约 `0.36 m`，理想回到 Y 原点 |
| `8~10 s` | 停止 | `0` | 原地等待 `2 s` |
| `10~13 s` | 左移 | `vx = +0.12 m/s` | 向左约 `0.36 m` |
| `13~15 s` | 停止 | `0` | 原地等待 `2 s` |
| `15~18 s` | 右移 | `vx = -0.12 m/s` | 向右约 `0.36 m`，理想回到 X 原点 |
| `18~20 s` | 停止 | `0` | 原地等待 `2 s` |
| `20~23 s` | 原地旋转 | `wz = +0.25 rad/s` | 旋转约 `0.75 rad`，约 `43.0 deg` |
| `23 s` 以后 | 停止 | `0` | 持续停止 |

### 5.3 路径结论

| 项目 | 结论 |
| --- | --- |
| 代码确认的路径 | 前进 0.36 m -> 后退 0.36 m -> 左移 0.36 m -> 右移 0.36 m -> 原地旋转约 43 deg -> 停止 |
| 理想净平移 | 约 `0 m`，最终回到起点附近 |
| 理想最终朝向 | 相对初始方向旋转约 `+0.75 rad`，实际正方向取决于 `MECANUM_WZ_SIGN`、电机接线和机械方向 |
| 是否闭环保证 | 否。无编码器里程计闭环、无 IMU 航向闭环、无路径状态机 |
| 遇到激光急停时 | Demo 计时不会暂停；障碍解除后按“当前已流逝时间”继续，可能跳过部分动作 |

### 5.4 理论轮速

基于轮径 `0.075 m`，`0.12 m/s` 对应轮速约 `30.6 rpm`；旋转 `0.25 rad/s` 对应轮面速度约 `0.0675 m/s`，轮速约 `17.2 rpm`。

| 动作 | FL | FR | RL | RR |
| --- | ---: | ---: | ---: | ---: |
| 前进 | `+30.6 rpm` | `+30.6 rpm` | `+30.6 rpm` | `+30.6 rpm` |
| 后退 | `-30.6 rpm` | `-30.6 rpm` | `-30.6 rpm` | `-30.6 rpm` |
| 左移 | `-30.6 rpm` | `+30.6 rpm` | `+30.6 rpm` | `-30.6 rpm` |
| 右移 | `+30.6 rpm` | `-30.6 rpm` | `-30.6 rpm` | `+30.6 rpm` |
| 正向旋转 | `-17.2 rpm` | `+17.2 rpm` | `-17.2 rpm` | `+17.2 rpm` |

实际轮子正反方向还要乘以 `motor_manager.c` 中的 `g_motor_dir_sign[]`。当前默认全为 `+1`，源码注释也提示需要实车逐轮标定。

## 6. 主要问题与风险

| 优先级 | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| P0 | `main.c` 包含 `i2c.h`、`usart.h`、`gpio.h`，但工程目录中不存在这些文件 | 大概率直接编译失败 | 要么让 CubeMX 生成独立外设文件，要么删除这 3 个 include 并保持当前 `main.c` 内部初始化函数 |
| P0 | `atk_ms53l1m.c` 引用 `vl53l1_api.h`，但工程中未找到 VL53L1 API 头文件/源码 | 激光模块相关代码无法编译 | 补齐 ST VL53L1 API 及平台适配文件，并加入 include path/sourceEntries |
| P0 | RS485 方向脚默认 `PB1` 未在 `.ioc` 或 `MX_GPIO_Init()` 中配置为输出 | RS485 收发方向可能无法切换，电机无响应 | 在 CubeMX 配置实际 DE/RE 引脚为 GPIO Output，并生成 `RS485_DIR_GPIO_Port/Pin` 宏 |
| P1 | `g_motor_dir_sign[]` 默认全 `+1`，`MECANUM_WZ_SIGN` 也标注待实车确认 | 小车可能前后左右或旋转方向与代码相反 | 架空车体逐轮标定地址、安装位置、正反向，再固化方向参数 |
| P1 | 当前路径是开环 Demo，无位置/航向闭环 | 实车会因轮滑、地面摩擦、电机差异产生偏移 | 若目标是稳定路径，应加入编码器/IMU 闭环或路径状态机 |
| P1 | 激光无效即急停 | 激光未接好时小车不会进入 Demo，容易误判为电机问题 | 调试时先确认 `laser_ok`、距离值和 `laser_warning` |
| P1 | 急停解除后 Demo 不从中断点恢复，而是按原始 elapsed time 继续 | 障碍解除后路径不完整，可能直接跳到后续动作或停止 | 改为显式任务状态机，急停时暂停计时 |
| P1 | Modbus 超时仅 `10 ms`，全部为阻塞式收发 | 电机响应慢时容易误判超时，主循环也会被通信阻塞 | 先按驱动器实际响应时间放宽超时，再考虑 DMA/中断或非阻塞队列 |
| P1 | 停止阶段每 10 ms 调用 `Mecanum_Stop()`，会反复下发 4 电机零速 + 同步触发 | RS485 总线负载高，可能影响反馈读取和响应稳定性 | 只在状态切换时发送 Stop，保持状态时不重复刷命令 |
| P2 | `USART1/USART2` 已初始化但未使用 | 占用引脚和初始化时间 | 明确用途，未使用则可暂时关闭 |
| P2 | IMU 启动即开始 200 个样本陀螺校准，但运动 Demo 未等待校准完成 | IMU 数据可能未校准；当前不影响路径，因为路径未用 IMU | 若后续用 IMU 闭环，应等待 `imu_calibrated` 后再运动 |
| P2 | 工程注释在部分工具中显示为乱码 | 维护体验差，容易误读标定说明 | 统一源码编码为 UTF-8，并确认 IDE 编码设置 |
| P2 | 无硬件急停输入、无独立看门狗逻辑 | 实车安全冗余不足 | 增加物理急停、看门狗、通信失联停车策略 |

## 7. 建议验证步骤

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 补齐缺失的 `i2c/usart/gpio` 头文件策略与 VL53L1 API 后构建 | 工程能完整编译并生成 ELF |
| 2 | 在 CubeMX 中配置 RS485 方向脚，确认实际引脚和 `TX/RX` 电平 | 示波器或逻辑分析仪可看到 DE/RE 正确切换 |

| 4 | 架空车体执行单电机测试 `Mecanum_TestMotorDirection()` | 确认 `0x01~0x04` 是否对应 FL/FR/RL/RR，记录正反方向 |
| 5 | 标定 `g_motor_dir_sign[]` 与 `MECANUM_WZ_SIGN` | `MoveForward/Left/Rotate` 的方向与定义一致 |
| 6 | 激光前方放置安全距离大于 `600 mm` 的无遮挡环境 | `laser_valid=true`，`laser_warning<3`，Demo 能运行 |
| 7 | 地面低速运行并测量实际位移 | 理想平移回到起点附近，最终原地旋转约 43 度 |
| 8 | 若需要真实路径控制，新增状态机和闭环控制 | 急停可暂停/恢复，路径节点可被明确追踪 |

## 8. 推荐整改优先级

| 顺序 | 事项 | 原因 |
| --- | --- | --- |
| 1 | 先解决编译缺失文件 | 不可编译时无法验证任何硬件行为 |
| 2 | 配置 RS485 方向脚并验证 Modbus | 电机链路是底盘能否动作的核心 |
| 3 | 标定四轮地址与方向 | 不标定会导致路径方向不可预测 |
| 4 | 将 Demo 改成状态机 | 减少重复 Stop 命令，并解决急停后路径跳段 |
| 5 | 引入 IMU/编码器闭环 | 让“运行路径”从理想开环变成可控实车轨迹 |
