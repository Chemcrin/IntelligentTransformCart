# 树莓派通过 USB-TypeC/CH340N 控制 STM32 小车底盘方案

# 0. 核心要求：
不能因为增加新功能，而影响了小车的运行轨迹。优先保证小车可以按照现有轨迹完整运行

## 1. 系统目标

本方案用于实现：

| 目标            | 说明                                  |
| ------------- | ----------------------------------- |
| 树莓派发送控制命令     | 树莓派通过 USB 数据线向 STM32 发送运动指令         |
| STM32 接收并解析命令 | STM32 使用 `UART2` 接收 CH340N 转换后的串口数据 |
| STM32 控制小车底盘  | 根据指令控制电机 PWM、方向、速度闭环、姿态修正           |
| 路径运行中可被打断     | 在原有路径执行过程中，加入串口控制中断或控制优先级机制         |
| 支持状态查询        | 树莓派可以查询激光距离、偏航角、当前位置等信息             |

## 4. 树莓派会发送什么数据

树莓派端 `car_protocol.py` 发出的数据是 ASCII 字符串，以 `\r\n` 结尾。

也就是每一帧格式为：

```
$命令,参数\r\n
```

### 4.1 运动命令

| 树莓派调用          | STM32 接收到的数据 | 十六进制                      | 含义  |
| -------------- | ------------ | ------------------------- | --- |
| `forward()`    | `$FWD\r\n`   | `24 46 57 44 0D 0A`       | 前进  |
| `backward()`   | `$BACK\r\n`  | `24 42 41 43 4B 0D 0A`    | 后退  |
| `left()`       | `$LEFT\r\n`  | `24 4C 45 46 54 0D 0A`    | 左移  |
| `right()`      | `$RIGHT\r\n` | `24 52 49 47 48 54 0D 0A` | 右移  |
| `stop_async()` | `$STOP\r\n`  | `24 53 54 4F 50 0D 0A`    | 停止  |

### 4.2 转向命令

| 树莓派调用                | STM32 接收到的数据  | 含义        |
| -------------------- | ------------- | --------- |
| `turn_cw_async(90)`  | `$CW,90\r\n`  | 顺时针转 90 度 |
| `turn_ccw_async(45)` | `$CCW,45\r\n` | 逆时针转 45 度 |

### 4.3 查询命令

|树莓派发送|STM32 应回复|含义|
|---|---|---|
|`$LASER\r\n`|`$LASER,1234\r\n`|返回激光测距，单位 mm|
|`$YAW\r\n`|`$YAW,-45.2\r\n`|返回当前偏航角|
|`$STOP\r\n`|`$OK\r\n`|确认停止成功|

## 5. STM32 总体控制逻辑

STM32 端不要在串口中断里直接控制电机。推荐结构是：

```
UART2 接收中断 / DMA 空闲中断
        |
        v
只负责接收数据、保存命令、置位标志
        |
        v
主循环 / 控制任务读取命令
        |
        v
更新小车运动状态机
        |
        v
定时器周期任务执行底盘控制
        |
        v
PWM 输出到电机驱动
```

推荐控制周期：

|任务|周期|
|---|---|
|UART 接收|中断触发|
|命令解析|主循环或 5ms 任务|
|电机速度 PID|5ms 或 10ms|
|姿态 yaw 修正|5ms 或 10ms|
|路径状态机|10ms 或 20ms|
|激光避障|20ms 或 50ms|

## 6. STM32 命令解析方案

### 6.1 接收缓存

建议设置一个串口接收缓冲区：

```
#define UART_RX_BUF_SIZE 128

uint8_t uart2_rx_byte;
char cmd_buf[UART_RX_BUF_SIZE];
volatile uint16_t cmd_index = 0;
volatile uint8_t cmd_ready = 0;
```

### 6.2 接收规则

|条件|处理|
|---|---|
|收到普通字符|存入 `cmd_buf`|
|收到 `\r`|忽略或保留|
|收到 `\n`|一帧结束，置位 `cmd_ready = 1`|
|缓冲区满|清空，防止溢出|

收到：

```
$FWD\r\n
```

STM32 最终解析到：

```
$FWD
```

## 7. 底盘运动控制方案

如果你的小车是麦克纳姆轮，推荐抽象为三个速度：

|参数|含义|
|---|---|
|`vx`|前后速度，前进为正|
|`vy`|左右速度，右移为正|
|`wz`|旋转速度，顺时针为正|

运动指令映射如下：

|命令|vx|vy|wz|小车动作|
|---|---|---|---|---|
|$FWD|`+V`|`0`|yaw 修正|前进|
|$BACK|`-V`|`0`|yaw 修正|后退|
|$LEFT|`0`|`-V`|`0`|左移|
|$RIGHT|`0`|`+V`|`0`|右移|
|$STOP|`0`|`0`|`0`|停止|
|`$CW,90`|`0`|`0`|`+W`|右转到目标角度|
|`$CCW,45`|`0`|`0`|`-W`|左转到目标角度|

麦克纳姆轮混控：

```
void chassis_set(float vx, float vy, float wz)
{
    float fl = vx + vy + wz;
    float fr = vx - vy - wz;
    float rl = vx - vy + wz;
    float rr = vx + vy - wz;

    motor_set_speed(MOTOR_FL, fl);
    motor_set_speed(MOTOR_FR, fr);
    motor_set_speed(MOTOR_RL, rl);
    motor_set_speed(MOTOR_RR, rr);
}
```

如果是普通差速底盘，则简化为：

|命令|左轮|右轮|
|---|---|---|
|$FWD|`+V`|`+V`|
|$BACK|`-V`|`-V`|
|$LEFT|`-V`|`+V`|
|$RIGHT|`+V`|`-V`|
|$STOP|`0`|`0`|

typedef enum {

    MODE_FORWARD,
    MODE_BACKWARD,
    MODE_LEFT,
    MODE_RIGHT,
    MODE_TURN,
    MODE_PATH_RUN,

    MODE_EMERGENCY_STOP

命令对应状态转换：

|收到命令|状态变化|
|---|---|
|$FWD|`MODE_FORWARD`|
|$BACK|`MODE_BACKWARD`|
|$LEFT|`MODE_LEFT`|
|$RIGHT|`MODE_RIGHT`|
|`$CW,angle`|`MODE_TURN`，设置目标角度|
|`$CCW,angle`|`MODE_TURN`，设置目标角度|
|$STOP|`MODE_IDLE` 或 `MODE_EMERGENCY_STOP`|

|$YAW|不改变运动状态，只回复角度|

## 9. 在现有运行路径中增加“中断”调控位置

这里建议分成两层：

|类型|作用|
|---|---|
|UART 硬件中断|保证树莓派命令能实时进入 STM32|
|路径控制中断机制|让当前路径执行过程可以被外部命令暂停、修正、恢复或终止|

不要在 UART 中断里直接修改复杂路径。更安全的方式是设置控制标志。

### 9.1 新增控制优先级

建议优先级如下：

|优先级|控制来源|说明|
|---|---|---|
|最高|急停 / 避障|立即停车|
|高|树莓派实时命令|$STOP、$FWD、$LEFT 等|
|中|位置修正命令|偏移修正、角度修正|
|低|原有自动路径|正常循迹或路径执行|

当自动路径正在运行时，如果树莓派发送 $STOP：

```
当前路径立即暂停 -> 底盘速度清零 -> 回复 $OK
```

如果树莓派发送 $LEFT：

```
当前路径暂停 -> 执行左移修正 -> 等待 STOP 或新的恢复命令
```

## 11. 具体实现框架

### 11.1 UART2 接收中断

```
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2)
    {
        uint8_t ch = uart2_rx_byte;

        if (ch == '\n')
        {
            cmd_buf[cmd_index] = '\0';
            cmd_ready = 1;
            cmd_index = 0;
        }
        else if (ch != '\r')
        {
            if (cmd_index < UART_RX_BUF_SIZE - 1)
            {
                cmd_buf[cmd_index++] = ch;
            }
            else
            {
                cmd_index = 0;
            }
        }

        HAL_UART_Receive_IT(&huart2, &uart2_rx_byte, 1);
    }
}
```

初始化时启动接收：

```
HAL_UART_Receive_IT(&huart2, &uart2_rx_byte, 1);
```

### 11.3 命令解析

```
void parse_rpi_command(char *cmd)
{
    if (strcmp(cmd, "$FWD") == 0)
    {
        path_pause();
        car_mode = MODE_FORWARD;
        target_yaw = imu_get_yaw();
        uart_send("$OK\r\n");
    }
    else if (strcmp(cmd, "$BACK") == 0)
    {
        path_pause();
        car_mode = MODE_BACKWARD;
        target_yaw = imu_get_yaw();
        uart_send("$OK\r\n");
    }
    else if (strcmp(cmd, "$LEFT") == 0)
    {
        path_pause();
        car_mode = MODE_LEFT;
        uart_send("$OK\r\n");
    }
    else if (strcmp(cmd, "$RIGHT") == 0)
    {
        path_pause();
        car_mode = MODE_RIGHT;
        uart_send("$OK\r\n");
    }
    else if (strcmp(cmd, "$STOP") == 0)
    {
        car_mode = MODE_IDLE;
        chassis_set(0, 0, 0);
        uart_send("$OK\r\n");
    }
    else if (strncmp(cmd, "$CW,", 4) == 0)
    {
        float angle = atof(cmd + 4);
        path_pause();
        turn_start(angle);
        uart_send("$OK\r\n");
    }
    else if (strncmp(cmd, "$CCW,", 5) == 0)
    {
        float angle = atof(cmd + 5);
        path_pause();
        turn_start(-angle);
        uart_send("$OK\r\n");
    }
    else if (strcmp(cmd, "$LASER") == 0)
    {
        char tx[32];
        sprintf(tx, "$LASER,%d\r\n", laser_get_mm());
        uart_send(tx);
    }
    else if (strcmp(cmd, "$YAW") == 0)
    {
        char tx[32];
        sprintf(tx, "$YAW,%.1f\r\n", imu_get_yaw());
        uart_send(tx);
    }
    else
    {
        uart_send("$ERR\r\n");
    }
}
```

## 12. 运动任务实现

```
void motion_task(void)
{
    float yaw_now = imu_get_yaw();
    float yaw_error = angle_diff(target_yaw, yaw_now);
    float yaw_fix = pid_yaw_calculate(yaw_error);

    switch (car_mode)
    {
        case MODE_FORWARD:
            chassis_set(BASE_SPEED, 0, yaw_fix);
            break;

        case MODE_BACKWARD:
            chassis_set(-BASE_SPEED, 0, yaw_fix);
            break;

        case MODE_LEFT:
            chassis_set(0, -BASE_SPEED, 0);
            break;

        case MODE_RIGHT:
            chassis_set(0, BASE_SPEED, 0);
            break;

        case MODE_TURN:
            turn_task();
            break;

        case MODE_IDLE:
        default:
            chassis_set(0, 0, 0);
            break;
    }
}
```

## 16. 最关键的设计原则

|原则|原因|
|---|---|
|树莓派只发高级命令|Linux 实时性差，不适合直接闭环控电机|
|STM32 做底层运动控制|STM32 实时性强，适合 PWM、编码器、PID|
|串口中断只收数据|避免中断里执行复杂控制导致系统卡顿|
|控制逻辑放状态机|方便路径运行、暂停、恢复、急停|
|所有命令都以 `\r\n` 结束|与当前 Python 协议一致|
|查询命令必须回复固定格式|树莓派端 `get_distance()`、`get_yaw()` 依赖格式匹配|

总结一下：你现在的 Type-C 连接方案本质上是“树莓派 USB 串口 -> CH340N -> STM32 UART2”。STM32 会收到 `$FWD\r\n`、`$STOP\r\n`、`$CW,90\r\n` 这类 ASCII 命令。最佳做法是在 STM32 上用 UART2 中断或 DMA 接收命令，用状态机管理小车运动，用定时器周期任务执行底盘 PID 和路径控制，并在原有路径任务中加入暂停、修正、恢复、急停这些高优先级控制入口。

# 树莓派插入式微调控制方案

## Summary

| 项目 | 决策 |
|---|---|
| 控制链路 | 树莓派 USB -> CH340N -> STM32 `USART2`，`115200 8N1` |
| 控制模式 | 固定轨迹运行中可被树莓派命令抢占，执行完单条微调后自动回到原轨迹 |
| 方向微调 | `$FWD/$BACK/$LEFT/$RIGHT` 每条默认移动 `100mm` |
| 停止语义 | `$STOP` 为急停暂停，不自动恢复 |
| 恢复默认 | 因本次只做必需命令，`$STOP` 后收到下一条运动/转向命令时执行插入动作，随后恢复原轨迹 |

## Public Interfaces

| 接口 | 行为 |
|---|---|
| `$FWD\r\n` | 暂停当前轨迹，前进 `100mm`，回复 `$OK`，完成后恢复轨迹 |
| `$BACK\r\n` | 暂停当前轨迹，后退 `100mm`，回复 `$OK`，完成后恢复轨迹 |
| `$LEFT\r\n` | 暂停当前轨迹，左移 `100mm`，回复 `$OK`，完成后恢复轨迹 |
| `$RIGHT\r\n` | 暂停当前轨迹，右移 `100mm`，回复 `$OK`，完成后恢复轨迹 |
| `$CW,90\r\n` | 暂停当前轨迹，顺时针旋转 `90°`，回复 `$OK`，完成后恢复轨迹 |
| `$CCW,45\r\n` | 暂停当前轨迹，逆时针旋转 `45°`，回复 `$OK`，完成后恢复轨迹 |
| `$STOP\r\n` | 立即停止并暂停轨迹，回复 `$OK`，不自动恢复 |
| `$LASER\r\n` | 回复 `$LASER,<distance_mm>\r\n`，不改变运动状态 |
| `$YAW\r\n` | 回复 `$YAW,<yaw_deg>\r\n`，不改变运动状态 |

## Test Plan

| 场景 | 验证方式 |
|---|---|
| USART2 接收 | 树莓派或串口助手发送 `$FWD\r\n`，确认 STM32 回复 `$OK\r\n` |
| 单条微调 | 空闲状态发送 `$LEFT\r\n`，确认小车左移约 `100mm` 后停止 |
| 轨迹中抢占 | 固定轨迹直行时发送 `$RIGHT\r\n`，确认立即中断、右移 `100mm`、再继续原轨迹 |
| 急停暂停 | 轨迹运行时发送 `$STOP\r\n`，确认立即停车且不自动继续 |
| 急停后恢复 | `$STOP` 后发送 `$FWD\r\n`，确认执行 `100mm` 前进插入动作后回到原轨迹 |
| 转向命令 | 发送 `$CW,90\r\n` / `$CCW,45\r\n`，确认转向方向和角度趋势正确 |
| 查询命令 | 发送 `$LASER\r\n`、`$YAW\r\n`，确认返回格式可被树莓派端解析 |
| 异常输入 | 发送缺少 `$`、未知命令、超长字段，确认回复 `$ERR` 或丢弃且不影响轨迹 |
