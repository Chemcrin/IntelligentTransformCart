# 智能物流小车工程变更说明

> 工程：`smart_logistics_car_integrated`  
> 日期：2026-06-16  
> 修改依据：`工程修改任务书.md`、`项目审查报告_2026-06-09.md`、`智能物流小车-硬件平台技术手册V3.md`  
> 目标：修正 UART 分配错误，清理临时模块，补齐树莓派回传、CSV 调试与闭环直线控制能力。

## 1. 最终硬件链路

本次修改后，工程以以下链路为准：

| 功能 | 外设 | STM32 引脚 | 代码绑定 | 说明 |
|---|---|---|---|---|
| ZDT_X42 电机 / RS485 / Modbus | `USART1` | `PA9_TX / PA10_RX` | `Mecanum_Init(&huart1)` | 正式电机总线 |
| 树莓派控制与状态回传 | `USART2` | `PA2_TX / PA3_RX` | `RemoteCmd_Init(&huart2)` | ASCII 命令、状态、IMU/激光回传、CSV 调试 |
| JY61P + ATK-MS53L1M | `I2C1` | `PB6_SCL / PB7_SDA` | `Board_App_Init/Loop()` | 传感器共总线 |
| `USART3` | 空置 | `PB10/PB11` 未配置 | 无业务绑定 | 任务书要求 UART3 保持空置 |

### 关于 CSV 串口的处理

任务书中同时出现了两个冲突要求：

1. 电机通信必须使用 `UART1/USART1`，`UART3` 保持空置；
2. CSV 调试输出又要求使用 `UART1`。

由于硬件标准已把 `UART1` 固定为电机 RS485 总线，本次实现选择保留 `UART1` 给电机，CSV 调试流改走 `USART2`。这样不会破坏 PCB 既定电机链路，也不会重新占用 `USART3`。若后续要单独用 USB-TTL 抓 CSV，请接到 `USART2 PA2/PA3` 或临时关闭树莓派命令链路。

## 2. 串口与外设初始化修改

### 2.1 `Core/Src/main.c`

修改内容：

- 删除 `huart3` 引用。
- 删除 `MX_USART3_UART_Init()` 调用。
- 电机初始化从 `Mecanum_Init(&huart3)` 改为 `Mecanum_Init(&huart1)`。
- 树莓派链路保持 `RemoteCmd_Init(&huart2)`。
- 主循环增加 `CSV_Debug_Loop(&huart2)`。

当前主循环顺序：

```c
while (1)
{
    Board_App_Loop();
    CSV_Debug_Loop(&huart2);
    RemoteCmd_Loop();
    Mecanum_PeriodicTask();
    HAL_Delay(APP_LOOP_PERIOD_MS);
}
```

### 2.2 `Core/Src/usart.c` 与 `Core/Inc/usart.h`

修改内容：

- 保留 `huart1`、`huart2`。
- 删除 `huart3`、`MX_USART3_UART_Init()`、`USART3` MSP 初始化/反初始化。
- `USART1` 维持 `115200 8N1`，用于电机 RS485。
- `USART2` 维持 `115200 8N1`，用于树莓派命令和状态回传。
- 在 `USART2` MSP 初始化中启用 `USART2_IRQn`。

### 2.3 `Core/Src/stm32f1xx_it.c` 与 `Core/Inc/stm32f1xx_it.h`

新增：

```c
void USART2_IRQHandler(void)
{
    HAL_UART_IRQHandler(&huart2);
}
```

原因：`RemoteCmd_Init()` 使用 `HAL_UART_Receive_IT()` 单字节中断接收，如果没有 `USART2_IRQHandler()`，树莓派发送的命令不会被 HAL 回调处理。

### 2.4 `smart_logistics_car_integrated.ioc`

修改内容：

- 删除 `USART3` 外设。
- 删除 `PB10/PB11` 的 USART3 配置。
- 保留 `USART1`、`USART2`、`I2C1`、`SYS`、`RCC`、`NVIC`。
- 增加 `USART2_IRQn` 配置。
- `ProjectManager.StackSize` 调整为 `0x800`，给 CSV 格式化和传感器状态回传留出更充足栈空间。

| 参数 | 修改后 | 说明 |
|---|---:|---|
| `MS53L1M_UPDATE_PERIOD_MS` | `150U` | 激光轮询周期回到 100–200 ms 级别 |
| `VL53L1_SetMeasurementTimingBudgetMicroSeconds` | `140000U` | Long 模式较稳定的时间预算 |
| `VL53L1_SetInterMeasurementPeriodMilliSeconds` | `150U` | 与轮询周期一致 |
| `MS53L1M_WARN_DISTANCE_MM` | `500U` | 预警距离 |
| `MS53L1M_SLOW_DISTANCE_MM` | `300U` | 减速提示距离 |
| `MS53L1M_STOP_DISTANCE_MM` | `100U` | 急停距离统一为 10 cm |
| `MS53L1M_TOO_CLOSE_CONFIRM_COUNT` | `2U` | 连续 2 次过近确认后置位 |

### 3.3 安全逻辑变化

旧逻辑中，激光无效和障碍物过近都会直接触发急停锁。新逻辑中二者分开处理：

| 情况 | 新处理 |
|---|---|
| `laser_valid == false` | 置位 `laser_fault`，通过状态帧上报，但不直接伪装成障碍物急停 |
| `laser_warning >= 3` 且距离有效 | 触发激光急停锁，调用 `Mecanum_EmergencyStop()` |
| 急停后障碍物移除 | 需要发送 `CLR` / `CLEAR` 才能解除锁定 |

| `UserModules/remote_cmd/remote_cmd.c/h` | 新增 `SC ON/OFF/?` 命令 |

### 5.3 控制策略

控制器只在“前进/后退直线”条件下自动介入：

- `|vy_mps| >= STRAIGHT_CONTROL_MIN_SPEED_MPS`
- `|vx_mps| <= STRAIGHT_CONTROL_VX_EPS_MPS`
- `|wz_radps| <= STRAIGHT_CONTROL_WZ_EPS_RADPS`
- IMU 数据有效且完成静止零偏标定

进入直线控制时，系统记录当前 yaw 作为目标航向。周期运行时：

1. 从 `Sensor_GetSnapshot()` 读取当前 yaw。
2. 计算 `target_yaw - current_yaw`，并 wrap 到 `[-pi, pi]`。
3. 航向 PID 输出 `yaw_correction`。
4. 如果电机反馈在线，读取左右轮平均 RPM，计算左右差速修正 `lr_correction`。
5. 将 `yaw_correction + lr_correction` 限幅后叠加到目标 `wz_radps`。
6. 用修正后的速度向量继续走原有麦轮逆解和电机 RPM 限幅。

### 5.4 API

```c
void StraightControl_Init(void);
void StraightControl_Enable(uint8_t enable);
uint8_t StraightControl_IsEnabled(void);
void StraightControl_Reset(void);
float StraightControl_PIDCalculate(StraightPid_t *pid, float error, float dt_s);
MecanumVelocity_t StraightControl_Apply(const MecanumVelocity_t *target, float dt_s);
StraightControlStatus_t StraightControl_GetStatus(void);
```

麦轮层新增封装：

```c
void Mecanum_EnableStraightControl(uint8_t enable);
uint8_t Mecanum_IsStraightControlEnabled(void);
MecanumResult_t Mecanum_MoveForwardClosedLoop(float speed_mps);

```

### 5.5 默认参数

| 宏 | 默认值 | 说明 |
|---|---:|---|
| `STRAIGHT_CONTROL_ENABLE_DEFAULT` | `1u` | 上电默认启用直线控制 |
| `STRAIGHT_CONTROL_MIN_SPEED_MPS` | `0.03f` | 低于该速度不介入，避免低速抖动 |
| `STRAIGHT_CONTROL_MAX_WZ_RADPS` | `0.40f` | 航向修正最大角速度 |
| `STRAIGHT_CONTROL_YAW_DEADBAND_RAD` | `0.0087f` | 约 0.5° 死区 |
| `STRAIGHT_YAW_KP` | `1.20f` | 航向环比例 |
| `STRAIGHT_YAW_KI` | `0.05f` | 航向环积分 |
| `STRAIGHT_YAW_KD` | `0.02f` | 航向环微分 |
| `STRAIGHT_LR_KP` | `0.0010f` | 左右轮反馈差比例 |
| `STRAIGHT_LR_KI` | `0.0001f` | 左右轮反馈差积分 |
| `STRAIGHT_LR_KD` | `0.0000f` | 左右轮反馈差微分，默认关闭 |

### 5.6 调试步骤

1. 确认上电时车体静止，等待 `imu_calibrated=1`。
2. 低速测试：发送 `SC ON`，再发送 `VEL 0 0.05 0`。
3. 观察 `SC?` 返回的 `yaw_err_rad` 和 `wz_corr`。
4. 若小车仍缓慢偏航，逐步增大 `STRAIGHT_YAW_KP`。
5. 若出现左右摆动，降低 `STRAIGHT_YAW_KP` 或增大 `STRAIGHT_CONTROL_YAW_DEADBAND_RAD`。
6. 若长期存在稳定偏差，再小幅增加 `STRAIGHT_YAW_KI`。
7. 若修正反向，将 `MECANUM_WZ_SIGN` 或 `STRAIGHT_LR_CORRECTION_SIGN` 取反后重新测试。
8. 轮速反馈调参前，必须逐个确认四个 ZDT_X42 地址、方向和反馈 rpm 符号。

### 5.7 防饱和与防抖措施

- PID 积分项使用 `integral_min/integral_max` 限幅。
- 输出修正使用 `STRAIGHT_CONTROL_MAX_WZ_RADPS` 限幅。
- 目标速度过低时不启用闭环，避免电机静摩擦区抖动。
- yaw 和左右轮 RPM 均设置 deadband。
- `StraightControl_Reset()` 会在停止、急停、故障清除和非直线命令时清空积分。

### 5.8 当前边界

该功能是“航向保持 + 轮速差修正”，不是完整里程闭环。它能改善前进/后退直线偏航，但不能保证走指定距离、转指定角度或执行固定路径。路径动作层仍需要后续增加里程估计和动作完成判据。

### 6.1 新增文件

| 文件 | 作用 |

### 6.2 编译开关

```c
#define CSV_DEBUG_ENABLE 1U
```

当 `CSV_DEBUG_ENABLE == 0U` 时，`CSV_Debug_Loop()` 在头文件中变成内联空函数，CSV 源码通过 `#if` 不参与实际功能逻辑。

### 6.3 输出格式

字段顺序：

```text
timestamp_ms, accelX_g, accelY_g, accelZ_g, gyroX_dps, gyroY_dps, gyroZ_dps, roll_deg, pitch_deg, yaw_deg

```

实现细节：

- 时间戳：`HAL_GetTick()`。
- 数据来源：`g_imu_ax_g`、`g_imu_ay_g`、`g_imu_az_g`、`g_imu_gx_dps`、`g_imu_gy_dps`、`g_imu_gz_dps`、`g_imu_roll_deg`、`g_imu_pitch_deg`、`g_imu_yaw_deg`。
- 保留 3 位小数。
- 局部缓冲区长度 `160` 字节，满足任务书“≥128 字节”的要求。
- 每 10 次主循环输出一行。
- 暂时使用 `HAL_UART_Transmit()` 阻塞发送，源码中已标注 `TODO: 改为 DMA 发送`。

## 7. 树莓派远程控制与数据回传

### 7.1 接收链路

- 串口：`USART2`。
- 接收方式：`HAL_UART_Receive_IT()` 单字节中断。
- 行结束：支持 `\n` 或 `\r\n`。
- 心跳超时：`REMOTE_CMD_HEARTBEAT_TIMEOUT_MS = 600U`。
- 状态上报周期：`REMOTE_CMD_STATUS_PERIOD_MS = 100U`。

### 7.2 命令列表

| 命令 | 作用 |
|---|---|
| `HB` | 心跳刷新 |
| `VEL <vx> <vy> <wz>` | 设置速度，单位 m/s、m/s、rad/s |
| `STOP` | 控制停车 |
| `ESTOP` | 软件急停并进入锁定 |
| `CLR` / `CLEAR` | 清除激光/心跳/急停锁定，前提是激光不再过近 |
| `ZERO` | 停车并将当前 yaw 置零 |
| `GYROCAL` | 运行期陀螺零偏标定，要求车体静止 |
| `ACCCAL` | 调用 JY61P 加速度计校准 |
| `STAT?` / `STATUS?` | 立即返回综合状态 |
| `IMU?` | 返回完整 IMU 数据 |
| `LASER?` | 返回完整激光数据 |
| `SENS?` | 返回 IMU + 激光摘要 |
| `SENS_STREAM ON/OFF` | 开关周期传感器摘要流 |
| `SC ON/OFF/?` | 开关/查询直线闭环控制 |

### 7.3 状态回传内容

`STAT` 帧已扩展，包含：

- 系统时间
- 链路状态与心跳超时标志
- 激光急停、激光故障、激光预警等级
- 目标速度 `vx/vy/wz`
- 激光原始距离、滤波距离
- IMU 有效/校准状态
- yaw、pitch、roll、gyro_z、车体系加速度
- 传感器 fault flags
- 直线闭环开关状态

## 8. RS485 方向控制

本次未修改 RS485 方向控制，保持：

```c
#define MODBUS_USE_RS485_DIR_GPIO 0u
```

原因：当前开发板到 RS485 模块只连接 `UART1 TX/RX`，没有分配 `DE/RE` GPIO。若后续确认 RS485 模块必须由 STM32 控制方向，可使用 `mecanum_config.h` 中预留的条件配置：

```c
#define MODBUS_USE_RS485_DIR_GPIO 1u
#define RS485_DIR_GPIO_Port GPIOB
#define RS485_DIR_Pin       GPIO_PIN_1
```

届时需要在 CubeMX 中把 `PB1` 配置为 GPIO Output，并飞线连接到 RS485 模块的 `DE/RE` 控制端。当前版本不需要飞线。

## 11. 烧录前建议检查

1. 确认电机 RS485 模块实际接到 `PA9/PA10`。
2. 确认树莓派/USB-TTL 接到 `PA2/PA3`。
3. 上电时保持小车静止，等待 IMU 标定完成。
4. 先发送 `HB`，再发送 `STAT?`、`IMU?`、`LASER?` 确认回传。
5. 低速测试：`VEL 0 0.05 0`，不要直接高速测试。
6. 激光急停测试先用低速接近障碍物，确认 100 mm 阈值和真实制动距离。
7. 若 CSV 调试开启，上位机串口会混合收到 CSV 行和 `STAT/SENS/ACK` 行；如果只需要命令状态，设置 `CSV_DEBUG_ENABLE` 为 `0U` 后重新编译。
