## 1. 项目概览

### 1.1 项目目标

本项目制作了一台面向智能物流搬运场景的小车。小车需要在比赛场地中按照实际路线行驶，识别需要搬运的物料，并将物料搬运到指定地点投放。

| 目标 | 具体说明 |
|---|---|
| 路线行驶 | 小车能够按照比赛场地路线执行前进、后退、横移、转向、等待、停止等动作 |
| 视觉识别 | 树莓派通过摄像头进行视觉识别，可使用 YOLO 识别不同颜色的球与桶 |
| 二维码扫描 | 树莓派能够扫描二维码，获取任务信息或搬运顺序 |
| 上位机调度 | 树莓派作为上位机，同时控制底盘 STM32 与机械臂 STM32 |
| 底盘控制 | 底盘 STM32 负责麦克纳姆轮运动控制和四个 ZDT-X42 电机通信 |
| 机械臂搬运 | 机械臂控制板 STM32 内部编写动作组，能够执行预定抓取与放置动作 |
| 整车协同 | 树莓派根据识别与扫码结果，指导底盘移动和机械臂抓取 / 放置 |

### 1.2 项目最终形态

| 模块 | 硬件 / 软件 | 职责 |
|---|---|---|
| 树莓派上位机 | 树莓派 4B、摄像头、YOLO、二维码识别程序、串口通信脚本 | 视觉识别、二维码扫描、任务调度、向两块 STM32 下发指令 |
| 底盘 STM32 | STM32F103C8T6、USART、I2C、HAL 工程 | 接收树莓派指令或执行固定路线，控制麦轮底盘运动 |
| 机械臂 STM32 | 机械臂控制板 STM32、动作组程序、串口通信 | 接收树莓派指令，执行预设抓取、放置、复位等动作组 |
| 运动执行 | ZDT-X42 闭环步进电机、RS485、麦克纳姆轮 | 实现全向移动，包括前进、后退、左右横移、原地旋转 |
| 感知辅助 | JY61P IMU、ATK-MS53L1M 激光测距 | 为后续航向校准、距离判断、安全保护提供数据基础 |
| 机械结构 | 底盘、料盘、料框、机械臂、夹爪、相机支架 | 承载树莓派、摄像头、机械臂和物料搬运机构 |

|---|---|---|

## 2. 系统架构

### 2.1 总体架构

```text
+------------------------------+
|        Raspberry Pi          |
|  YOLO 识别 / 二维码扫描       |
|  任务调度 / 上位机控制         |
+---------------+--------------+
                |
     +----------+----------+
     |                     |
     v                     v
+------------+       +----------------+
| 底盘 STM32  |       | 机械臂 STM32     |
| 麦轮控制     |       | 动作组控制        |
| 电机通信     |       | 抓取 / 放置       |
+-----+------+       +--------+-------+
      |                       |
      v                       v
ZDT-X42 x4 + 麦轮底盘       机械臂 / 夹爪
```

### 2.2 三层职责划分

| 层级 | 设备 | 主要职责 | 为什么这样分工 |
|---|---|---|---|
| 上位机 / 决策层 | 树莓派 | 视觉识别、二维码扫描、任务逻辑、双串口调度 | 树莓派算力更适合运行 YOLO 和图像处理 |
| 实时底盘层 | 底盘 STM32 | 麦轮运动控制、ZDT 电机通信、固定路线执行、底盘安全状态 | STM32 实时性更好，适合稳定下发电机控制 |
| 机械执行层 | 机械臂 STM32 | 保存动作组、执行抓取、放置、复位等动作 | 将机械臂控制独立出来，避免底盘和机械臂逻辑互相干扰 |

### 2.3 串口通信架构

| 通信链路 | 连接对象 | 通信方式 | 作用 |
|---|---|---|---|
| 树莓派 <-> 底盘 STM32 | 树莓派串口 / USB 转串口 到底盘 STM32 USART | 串口通信 | 下发底盘速度、停止、路线控制、状态查询等命令 |
| 树莓派 <-> 机械臂 STM32 | 树莓派串口 / USB 转串口 到机械臂控制板 STM32 | 串口通信 | 下发动作组编号或动作命令，触发抓取、放置、复位 |
| 底盘 STM32 <-> ZDT-X42 | STM32 USART1 + RS485 | Modbus-RTU | 控制四个闭环步进电机 |
| 底盘 STM32 <-> IMU / 激光 | I2C1 PB6/PB7 | I2C | 读取姿态和测距数据 |

### 2.4 双 STM32 分工优势

| 优势 | 说明 |
|---|---|
| 降低单板复杂度 | 底盘 STM32 专注运动控制，机械臂 STM32 专注动作执行 |
| 提高实时性 | 底盘控制周期不被机械臂动作延时影响 |
| 便于调试 | 底盘和机械臂可分别烧录、测试、排查问题 |
| 便于复用动作组 | 机械臂动作组可由上位机直接调用，不必每次重新写轨迹 |
| 便于后续扩展 | 树莓派可继续增加视觉、日志、路径规划等高级能力 |

### 3.1 阶段推进

| 阶段 | 主要内容 | 形成成果 |
|---|---|---|
| 需求分析 | 明确比赛任务：路线行驶、物料识别、抓取、运输、投放 | 确定 STM32 + 树莓派 + 机械臂架构 |
| 硬件平台整理 | 梳理 STM32 引脚、树莓派、JY61P、激光、电机、机械结构 | 硬件平台技术手册、PCB 和机械模型资料 |

| 传感器接入 | 接入 JY61P IMU 与 ATK-MS53L1M 激光测距 | IMU、激光、传感器桥接层 |
| 树莓派视觉开发 | 进行目标识别方案设计，补充 YOLO 与二维码识别能力 | 不同颜色球 / 桶识别、扫码任务读取方案 |
| 机械臂控制开发 | 在机械臂控制板 STM32 中编写动作组 | 可执行预定抓取和放置动作 |

| 固定路线兜底 | 为保证演示和比赛基础得分，制作固定路线独立运行版本 | `smart_logistics_car_integrated_route_2026-06-17` 工程 |
| 工程审查整改 | 检查时钟、栈、反馈、自动启动、安全联锁等问题 | 工程现状梳理、628 问题核验与修复方案 |
| 汇报整理 | 汇总项目过程、功能成果、技术特色、困难解决 | 本 Markdown 文档 |

### 3.2 关键路线选择

| 决策 | 原因 | 结果 |
|---|---|---|
| 树莓派作为上位机 | 视觉识别与任务调度需要更高算力和更灵活的软件环境 | 树莓派负责 YOLO、二维码扫描、双 STM32 调度 |
| 底盘和机械臂分开控制 | 两部分实时控制逻辑差异大，耦合后调试困难 | 两块 STM32 分别承担底盘与机械臂任务 |
| 机械臂采用动作组 | 抓取和放置动作重复性强，适合预先编排 | 树莓派只需触发动作组，不必实时控制每个关节 |
| 固定路线版本兜底 | 学期末时间有限，先保证小车能按照路线完成基础演示 | 主参考工程可独立运行固定路线 |
| 保留传感器闭环接口 | 固定路线可跑通后，还需要提高精度与安全性 | IMU、激光、RemoteCmd、StraightControl 等模块保留 |

## 5. 关键技术实现

### 5.1 底盘麦轮控制

| 项目 | 参数 / 实现 |
|---|---|
| 轮径 | 75 mm |
| 轮距 | 320 mm |
| 轴距 | 220 mm |
| 旋转耦合臂长 | 0.270 m |
| 最大平移速度 | 0.60 m/s |
| 最大角速度 | 1.50 rad/s |
| 轮速限制 | 500 RPM |
| 控制周期 | 20 ms |

逆运动学：

| 轮子 | 轮面速度公式 |
|---|---|
| 左前 FL | `vy - vx - K*wz` |
| 右前 FR | `vy + vx + K*wz` |
| 左后 RL | `vy + vx - K*wz` |
| 右后 RR | `vy - vx + K*wz` |

底盘控制流程：

```text
路线 / 树莓派命令
    -> Mecanum_SetVelocity(vx, vy, wz)
    -> ChassisControl 周期任务
    -> 麦轮逆运动学
    -> RPM 限幅与加速度限幅
    -> MotorManager
    -> ZDT_X42 Modbus 指令
    -> 四个电机执行
```

### 5.2 ZDT-X42 电机通信

| 项目 | 说明 |
|---|---|
| 通信方式 | USART1 + RS485 |
| 协议 | Modbus-RTU |
| 波特率 | 115200 |
| 电机地址 | FL=0x01，FR=0x02，RL=0x03，RR=0x04 |
| 当前策略 | 固定路线版本主要采用只发不收的开环控制 |
| 已有扩展 | 代码中保留读取实时速度的函数，后续可恢复电机反馈 |

### 5.3 树莓派 YOLO 视觉识别

| 项目 | 说明 |
|---|---|
| 运行平台 | 树莓派 |
| 识别算法 | YOLO 目标检测 |
| 识别对象 | 不同颜色的球与桶 |
| 输出信息 | 目标类别、颜色、位置框、置信度等 |
| 用途 | 判断当前需要搬运的目标，引导底盘对位和机械臂抓取 |

视觉识别流程：

```text
摄像头采集图像
    -> YOLO 推理
    -> 输出球 / 桶类别与颜色
    -> 与二维码任务信息匹配
    -> 选择目标
    -> 指导底盘移动或机械臂抓取
```

### 5.4 二维码扫描

| 项目 | 说明 |
|---|---|
| 扫描设备 | 树莓派摄像头 |
| 数据用途 | 获取比赛任务、搬运顺序、目标类别或目标位置 |
| 与 YOLO 的关系 | 二维码告诉“要搬什么”，YOLO 判断“目标在哪里” |
| 与机械臂的关系 | 扫码结果决定抓取对象和后续放置动作 |

二维码与视觉联动示例：

```text
二维码任务：搬运红球
    -> YOLO 查找红色球
    -> 底盘靠近目标
    -> 树莓派触发机械臂抓取动作组
    -> 底盘移动到投放区
    -> 树莓派触发机械臂放置动作组
```

### 5.5 树莓派双串口控制

树莓派同时承担上位机功能，与两块 STM32 都采用串口通信。

| 控制对象 | 指令内容 | 典型用途 |
|---|---|---|
| 底盘 STM32 | 速度、停止、路线、状态查询 | 控制小车移动到识别点、抓取点、投放点 |
| 机械臂 STM32 | 动作组编号、启动、停止、复位 | 执行抓取、抬升、放置、回零等预定动作 |

调度流程：

```text
树莓派识别任务
    -> 向底盘 STM32 发送移动 / 对位命令
    -> 到位后向机械臂 STM32 发送抓取动作组
    -> 抓取完成后向底盘 STM32 发送前往投放区命令
    -> 到位后向机械臂 STM32 发送放置动作组
    -> 完成任务并进入下一目标
```

### 5.6 机械臂动作组

| 动作组类别 | 作用 | 当前说明 |
|---|---|---|
| 抓取动作组 | 控制机械臂移动到抓取姿态并夹取物料 | 已在机械臂 STM32 中编写预定动作 |
| 放置动作组 | 控制机械臂移动到投放姿态并释放物料 | 已在机械臂 STM32 中编写预定动作 |
| 复位动作组 | 机械臂回到安全初始姿态 | 建议作为每轮任务前后的基础动作 |
| 停止 / 保护动作 | 中断当前动作或进入安全状态 | 可作为后续安全功能补充 |

动作组控制优势：

| 优势 | 说明 |
|---|---|
| 简化上位机逻辑 | 树莓派只需发送动作编号，不必实时控制每个舵机或关节 |
| 动作可重复 | 抓取和放置动作可以通过反复调试形成稳定流程 |
| 降低通信压力 | 串口只传动作触发命令，不传连续轨迹 |
| 便于现场调整 | 可在机械臂 STM32 侧修改动作组参数，而不影响底盘控制 |

### 5.7 IMU 与激光扩展

| 模块 | 已有能力 | 后续用途 |

| ATK-MS53L1M 激光 | 距离读取、滤波、预警 / 减速 / 停车阈值 | 靠近货架或障碍物时辅助判断距离 |

## 7. 遇到的困难与解决方案

### 7.1 树莓派同时控制两块 STM32

| 困难 | 表现 | 解决方案 |
|---|---|---|
| 通信对象多 | 树莓派既要控制底盘，又要控制机械臂 | 使用两路串口分别连接底盘 STM32 和机械臂 STM32 |
| 指令容易混淆 | 底盘速度命令和机械臂动作组命令格式不同 | 在上位机程序中区分两个串口对象和命令封装 |
| 调试复杂 | 底盘不动、机械臂不动可能来自不同链路 | 先分别测试两块 STM32，再进行整车联动 |

### 7.2 YOLO 视觉识别与任务匹配

| 困难 | 表现 | 解决方案 |
|---|---|---|
| 目标类别多 | 不同颜色的球和桶需要区分 | 使用 YOLO 直接识别颜色和类别 |
| 任务信息动态变化 | 比赛可能通过二维码给出任务 | 加入二维码扫描，将扫码结果与 YOLO 识别结果匹配 |
| 视觉到动作的转换困难 | 识别到目标后还要指导抓取 | 树莓派作为上位机，将识别结果转化为底盘对位和机械臂动作组触发 |

### 7.3 机械臂动作稳定性

| 困难 | 表现 | 解决方案 |
|---|---|---|
| 实时控制机械臂复杂 | 上位机直接控制每个关节会带来延迟和不稳定 | 将抓取与放置编写成 STM32 动作组 |
| 抓取动作需要重复调试 | 夹爪角度、机械臂姿态、物料位置都有影响 | 通过动作组固化稳定动作，现场只触发动作编号 |
| 底盘和机械臂需要协同 | 底盘未到位时抓取容易失败 | 树莓派统一调度，先底盘到位，再触发机械臂动作 |

### 7.4 麦轮底盘开环误差

| 困难 | 表现 | 当前解决 | 后续改进 |
|---|---|---|---|
| 没有完整里程闭环 | 实际距离可能与理论距离有偏差 | 固定路线低速开环兜底 | 恢复电机反馈或加入里程估计 |
| 转角受地面影响 | 90 度旋转可能存在误差 | 按时间和角速度估算 | 使用 IMU yaw 闭环 |
| 多段路线误差累积 | 终点偏差影响抓取 / 放置 | 横移和短段调整 | 使用视觉或传感器进行二次对位 |

### 7.5 RS485 与电机控制

| 困难 | 表现 | 解决方案 |
|---|---|---|
| 四个电机共用一条总线 | 需要区分不同电机 | 固定地址 FL=0x01、FR=0x02、RL=0x03、RR=0x04 |
| Modbus 帧容易出错 | CRC、寄存器、方向、速度格式都要正确 | 封装 `modbus_rtu` 和 `zdt_x42_modbus` 模块 |
| 实车方向可能相反 | 理论运动和实际运动不一致 | 保留电机方向符号和旋转方向标定参数 |

## 10. 可直接用于 PPT 的讲稿摘要

### 10.1 项目简介

本项目是一台基于 STM32、树莓派和机械臂的智能物流搬运小车。树莓派作为上位机，负责 YOLO 视觉识别、二维码扫描和任务调度；底盘 STM32 负责麦克纳姆轮底盘运动控制；机械臂 STM32 负责执行预设动作组，实现抓取和放置。整车能够按照比赛场地路线移动，识别不同颜色的球与桶，并通过机械臂完成物料搬运任务。

### 10.2 系统架构

| 模块 | 职责 |
|---|---|
| 树莓派 | 上位机、YOLO 识别、二维码扫描、双串口调度 |
| 底盘 STM32 | 麦轮控制、ZDT 电机通信、固定路线执行 |
| 机械臂 STM32 | 动作组执行、抓取、放置 |
| 摄像头 | 采集物料和二维码图像 |
| 麦轮底盘 | 实现全向移动和场地对位 |
| 机械臂 | 完成实际搬运动作 |

### 10.3 当前成果

| 成果 | 说明 |
|---|---|
| 固定路线底盘 | 可执行前进、后退、横移、旋转、停止 |
| 树莓派上位机 | 可作为视觉识别和任务调度中心 |
| YOLO 识别 | 可识别不同颜色的球与桶 |
| 二维码扫描 | 可读取任务信息并指导搬运流程 |
| 机械臂动作组 | 可完成预定抓取与放置动作 |
| 双 STM32 串口通信 | 树莓派分别控制底盘 STM32 和机械臂 STM32 |

### 10.4 技术特色

| 特色 | 汇报表述 |
|---|---|
| 分布式控制 | 一块 STM32 管底盘，一块 STM32 管机械臂，树莓派统一调度 |
| 视觉与执行结合 | YOLO 识别目标，二维码确定任务，机械臂动作组完成搬运 |
| 全向移动 | 麦轮底盘可横移和原地旋转，便于靠近目标和投放区 |
| 动作组复用 | 机械臂抓取和放置动作预先编排，提高稳定性 |
| 工程可扩展 | 后续可加入 IMU 闭环、激光安全和完整任务状态机 |

### 10.5 困难与解决

| 困难 | 解决思路 |
|---|---|
| 树莓派要同时管理视觉、底盘和机械臂 | 采用上位机架构和两路串口通信 |
| 视觉识别对象多 | 使用 YOLO 识别不同颜色的球与桶 |
| 任务顺序需要动态获取 | 使用二维码扫描读取任务信息 |
| 机械臂动作复杂 | 在机械臂 STM32 中固化抓取和放置动作组 |
| 底盘路线误差累积 | 先用固定路线兜底，后续恢复 IMU 和电机反馈闭环 |
